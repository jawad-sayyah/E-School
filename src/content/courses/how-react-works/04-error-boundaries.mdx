If a component throws while rendering, React can't trust the UI anymore, so by default it **removes the whole app** from the page. One bad product review would blank the entire shop. An **error boundary** contains the damage: it catches errors from the components below it and shows a fallback instead.

<Concept name="Writing an error boundary" id="writing">

Error boundaries are the one thing that still needs a **class component**: there's no hook for catching render errors. You write it once and reuse it everywhere. Click **Break the reviews**.

<ReactPlayground height={420} console>

```jsx file=/App.js
import { Component, useState } from "react";

class ErrorBoundary extends Component {
  state = { error: null };

  // 1. Render phase: switch to the fallback
  static getDerivedStateFromError(error) {
    return { error };
  }

  // 2. Commit phase: report it (to the console here, to Sentry in real apps)
  componentDidCatch(error, info) {
    console.log("Logged:", error.message);
  }

  render() {
    if (this.state.error) {
      return (
        <div className="oops">
          <p>Reviews couldn't load.</p>
          <button onClick={() => this.setState({ error: null })}>Try again</button>
        </div>
      );
    }
    return this.props.children;
  }
}

function Reviews({ broken }) {
  if (broken) throw new Error("Reviews API returned garbage");
  return <p>★★★★★ Best coffee in town</p>;
}

export default function App() {
  const [broken, setBroken] = useState(false);
  return (
    <>
      <h2>Coffee · $4</h2>
      <button onClick={() => setBroken(!broken)}>{broken ? "Fix" : "Break"} the reviews</button>
      <ErrorBoundary>
        <Reviews broken={broken} />
      </ErrorBoundary>
      <p>The rest of the page keeps working.</p>
    </>
  );
}
```

<Concept name="What boundaries catch, and what they don't" id="what-caught">

Boundaries catch errors thrown **while React is rendering** the components below them: in render, in lifecycle methods and in effects of those components.

They do **not** catch:

- errors in **event handlers** (they happen outside rendering; use `try`/`catch` and put the error in state),
- **async** code (`setTimeout`, a `fetch` callback) for the same reason,
- errors in the **boundary itself** (only boundaries above it can catch those).

A common pattern for async errors is to store them in state and throw during render, so the nearest boundary handles them like any other error.

</Concept>

<HowItWorks title="The two methods">

- **`static getDerivedStateFromError(error)`** runs during the render phase. It returns new state for the boundary (here `{ error }`), so the next render shows the fallback. It must be pure.
- **`componentDidCatch(error, info)`** runs during the commit phase, after the fallback is on screen. It's the place for side effects like logging. `info.componentStack` tells you which components the error passed through.

A boundary only needs the first to show a fallback; add the second to report errors.

</HowItWorks>

<GoDeeper title="react-error-boundary and resetting with keys">

Most teams use the small `react-error-boundary` package instead of writing the class:

```jsx file=ProductPage.jsx
import { ErrorBoundary } from "react-error-boundary";

<ErrorBoundary
  fallbackRender={({ error, resetErrorBoundary }) => (
    <div role="alert">
      <p>Something went wrong: {error.message}</p>
      <button onClick={resetErrorBoundary}>Try again</button>
    </div>
  )}
  resetKeys={[productId]}      // reset automatically when the product changes
>
  <Reviews productId={productId} />
</ErrorBoundary>
```

Without the library, you can reset a boundary by changing its `key`: `<ErrorBoundary key={productId}>` starts fresh for every product.

</GoDeeper>

```jsx tests file=/ErrorBoundary.test.js
import { render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import ErrorBoundary from "./ErrorBoundary";

function Bomb() {
  throw new Error("boom");
}

test("renders children when nothing throws", () => {
  render(
    <ErrorBoundary fallback={<p>Oops</p>}>
      <p>All good</p>
    </ErrorBoundary>,
  );
  expect(screen.getByText("All good")).toBeInTheDocument();
  expect(screen.queryByText("Oops")).not.toBeInTheDocument();
});

test("renders the fallback when a child throws", () => {
  render(
    <ErrorBoundary fallback={<p>Oops</p>}>
      <Bomb />
    </ErrorBoundary>,
  );
  expect(screen.getByText("Oops")).toBeInTheDocument();
});

test("only the broken part is replaced", () => {
  render(
    <>
      <p>Header</p>
      <ErrorBoundary fallback={<p>Oops</p>}>
        <Bomb />
      </ErrorBoundary>
    </>,
  );
  expect(screen.getByText("Header")).toBeInTheDocument();
});
```

```jsx solution file=/ErrorBoundary.js
import { Component } from "react";

export default class ErrorBoundary extends Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  render() {
    if (this.state.hasError) return this.props.fallback;
    return this.props.children;
  }
}
```
