Your whole app doesn't need to download before the first screen appears. A checkout page, a rich text editor or a chart library can load **when the user first needs it**. That's **code splitting**, and React does it with `lazy` and `<Suspense>`.

<Concept name="lazy + Suspense" id="lazy-suspense">

`lazy(() => import("./Reviews"))` returns a component that loads its code the first time it renders. While it loads, the component **suspends**, and the nearest `<Suspense>` above it shows its `fallback` instead. Click the button: the reviews take a second to "download".

<ReactPlayground height={360}>

```jsx file=/App.js
import { lazy, Suspense, useState } from "react";

// A fake slow network, so you can see the fallback
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const Reviews = lazy(() => delay(1200).then(() => import("./Reviews")));

export default function App() {
  const [show, setShow] = useState(false);
  return (
    <>
      <h2>Coffee</h2>
      <button onClick={() => setShow(true)}>Show reviews</button>
      {show && (
        <Suspense fallback={<p className="loading">Loading reviews…</p>}>
          <Reviews />
        </Suspense>
      )}
    </>
  );
}
```

```jsx file=/Reviews.js
export default function Reviews() {
  return (
    <ul>
      <li>★★★★★ Best coffee in town</li>
      <li>★★★★☆ Great, but the line is long</li>
    </ul>
  );
}
```

```css file=/styles.css
body { font-family: system-ui, sans-serif; padding: 16px; }
.loading { color: #888; font-style: italic; }
```

</ReactPlayground>

- `lazy` takes a function that returns a **promise of a module** with a `default` export. `import("./Reviews")` (a **dynamic import**) is exactly that; build tools like Vite turn it into a separate file.
- Declare lazy components at the **top level** of a module, never inside a component (it would restart the download on every render).
- Once loaded, the code is cached: showing the reviews again is instant.

</Concept>

<Concept name="Where to put boundaries" id="boundaries">

A `<Suspense>` boundary catches **every** suspending component below it, however deep. Where you put it decides what the user sees while waiting:

```jsx file=App.jsx
<Layout>
  <Suspense fallback={<PageSpinner />}>        {/* one boundary for the whole page */}
    <ProductPage />
  </Suspense>
</Layout>

<ProductPage>
  <ProductInfo />                              {/* shows right away */}
  <Suspense fallback={<ReviewsSkeleton />}>    {/* only the reviews wait */}
    <Reviews />
  </Suspense>
</ProductPage>
```

- Keep the **frame** of the page (header, navigation) outside boundaries, so it never disappears.
- Prefer **skeletons** shaped like the content over a spinner covering everything.
- Route-level splitting (one lazy component per page) is the most common use: each page is its own file.

</Concept>

<HowItWorks title="How suspending works">

When a lazy component renders before its code is ready, React doesn't get JSX back. Instead, the component signals "I'm waiting for this promise". React stops rendering that part of the tree, finds the nearest `<Suspense>` boundary above it, and commits the boundary's `fallback` instead. When the promise resolves, React tries rendering the component again, and this time it works.

The same mechanism also handles **data**: in React 19, `use(promise)` suspends until data arrives, so one `<Suspense>` can show a fallback while both code and data load. The React 19 course covers `use`.

</HowItWorks>

<GoDeeper title="Avoiding a flash of the fallback">

If an update (like switching tabs) makes an already visible part of the page suspend, replacing it with a spinner feels jumpy. Wrap that update in `startTransition` and React keeps showing the **old** content until the new content is ready:

```jsx file=Tabs.jsx
import { startTransition, useState } from "react";

function Tabs() {
  const [tab, setTab] = useState("info");
  function selectTab(next) {
    startTransition(() => setTab(next));   // keep the old tab visible while the new one loads
  }
  // …
}
```

Transitions and `useTransition` are covered in the Hooks course.

</GoDeeper>
