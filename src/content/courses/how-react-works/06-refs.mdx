React manages the DOM for you, but sometimes you need the **real element**: to focus an input, scroll to a message, measure a box or play a video. A **ref** gives you that, and it's also a box for values you want to keep between renders **without** re-rendering.

<Concept name="Refs to DOM elements" id="dom-refs">

`useRef(null)` creates an object `{ current: null }` that stays the same for the component's whole life. Pass it as the `ref` attribute of an element, and after the commit React puts the DOM node in `ref.current`.

<ReactPlayground height={300}>

```jsx file=/App.js
import { useRef } from "react";

export default function App() {
  const searchRef = useRef(null);
  const listEndRef = useRef(null);

  return (
    <>
      <input ref={searchRef} placeholder="Search products" />
      <button onClick={() => searchRef.current.focus()}>Focus search</button>
      <button onClick={() => listEndRef.current.scrollIntoView({ behavior: "smooth" })}>
        Jump to the end
      </button>
      <ul>
        {Array.from({ length: 30 }, (_, i) => (
          <li key={i}>Product {i + 1}</li>
        ))}
      </ul>
      <p ref={listEndRef}>That's everything!</p>
    </>
  );
}
```

</ReactPlayground>

Only read or use `ref.current` in **event handlers and effects**, not while rendering: during the first render the DOM node doesn't exist yet.

</Concept>

<Concept name="Refs for values that don't affect the screen" id="value-refs">

A ref is also a place to remember something that **shouldn't** trigger a render when it changes: a timer id, the previous value of a prop, whether a request is still in flight.

| | `useState` | `useRef` |
| --- | --- | --- |
| Changing it… | re-renders the component | does **not** re-render |
| Read it with… | `value` | `ref.current` |
| Use it for… | anything shown on screen | timer ids, DOM nodes, "instance variables" |

<ReactPlayground height={280}>

```jsx file=/App.js
import { useRef, useState } from "react";

export default function App() {
  const [seconds, setSeconds] = useState(0);
  const timerRef = useRef(null);

  function start() {
    if (timerRef.current) return; // already running
    timerRef.current = setInterval(() => setSeconds((s) => s + 1), 1000);
  }

  function stop() {
    clearInterval(timerRef.current);
    timerRef.current = null;
  }

  return (
    <p>
      Your order is being prepared: {seconds}s{" "}
      <button onClick={start}>Start</button> <button onClick={stop}>Stop</button>
    </p>
  );
}
```

</ReactPlayground>

The interval id is needed by `stop`, but showing it would be pointless, so it lives in a ref.

</Concept>

<Concept name="Refs to your own components: ref as a prop" id="ref-prop">

A `ref` on an HTML element gives you the DOM node. On **your own** component, you decide what it points at. In **React 19**, `ref` is a normal prop for function components: take it and pass it on.

```jsx file=TextInput.jsx
// React 19: ref is just a prop
function TextInput({ label, ref, ...rest }) {
  return (
    <label>
      {label} <input ref={ref} {...rest} />
    </label>
  );
}

function Checkout() {
  const emailRef = useRef(null);
  return (
    <>
      <TextInput label="Email" ref={emailRef} />
      <button onClick={() => emailRef.current.focus()}>Fix email</button>
    </>
  );
}
```

Before React 19 you had to wrap the component in **`forwardRef`** to receive a ref. You'll still see it in lots of existing code and libraries:

```jsx file=TextInput.jsx
// React 18 and earlier
const TextInput = forwardRef(function TextInput({ label, ...rest }, ref) {
  return (
    <label>
      {label} <input ref={ref} {...rest} />
    </label>
  );
});
```

</Concept>

<HowItWorks title="When React sets ref.current">

During the commit, after the DOM is updated, React sets `ref.current` to the new node; when the element is removed, it sets it back to `null`. That's why refs are ready inside event handlers (which run later) and effects (which run after the commit), but not during render.

Changing `ref.current` yourself is just mutating a plain object: React doesn't know or care, which is exactly why it doesn't re-render.

</HowItWorks>

<GoDeeper title="useImperativeHandle: exposing a small API">

Sometimes you don't want to give the parent the whole DOM node, only a couple of methods. `useImperativeHandle` lets the child decide what the ref holds:

```jsx file=VideoPlayer.jsx
function VideoPlayer({ src, ref }) {
  const videoRef = useRef(null);
  useImperativeHandle(ref, () => ({
    play: () => videoRef.current.play(),
    pause: () => videoRef.current.pause(),
  }));
  return <video ref={videoRef} src={src} />;
}

// parent: playerRef.current.play()  (but not playerRef.current.remove())
```

Use refs sparingly: most things (showing, hiding, changing text) should be done with state and props. Refs are for the imperative leftovers like focus, scroll, measuring and media.

</GoDeeper>

Clicking **Search** should put the cursor in the search box. `SearchBox` is your own component, so let it accept a `ref` (React 19 style: as a prop) and pass it to the input. Then use a ref in `App` to focus it.

```jsx starter file=/SearchBox.js
export default function SearchBox({ label }) {
  return (
    <label>
      {label} <input type="search" />
    </label>
  );
}
```

```jsx starter file=/App.js
import SearchBox from "./SearchBox";

export default function App() {
  return (
    <header>
      <SearchBox label="Find a drink" />
      <button>Search</button>
    </header>
  );
}
```

```jsx tests file=/App.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

test("the input isn't focused at first", () => {
  render(<App />);
  expect(screen.getByLabelText("Find a drink")).not.toHaveFocus();
});

test("clicking Search focuses the input", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "Search" }));
  expect(screen.getByLabelText("Find a drink")).toHaveFocus();
});
```

```jsx solution file=/SearchBox.js
export default function SearchBox({ label, ref }) {
  return (
    <label>
      {label} <input type="search" ref={ref} />
    </label>
  );
}
```

```jsx solution file=/App.js
import { useRef } from "react";
import SearchBox from "./SearchBox";

export default function App() {
  const searchRef = useRef(null);
  return (
    <header>
      <SearchBox label="Find a drink" ref={searchRef} />
      <button onClick={() => searchRef.current.focus()}>Search</button>
    </header>
  );
}
```
