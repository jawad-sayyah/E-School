Children render whenever their parent does. That's fine almost always, but when a child is **slow** to render (a big list, a chart), you can tell React to skip it when its props haven't changed.

<Concept name="memo: skip a render when props are the same" id="memo">

`memo(Component)` returns a version of the component that React only renders when **at least one prop changed** (compared with `Object.is`, one prop at a time). Type in the note: `ProductList` no longer logs.

<ReactPlayground height={360} console>

```jsx file=/App.js
import { memo, useState } from "react";

const ProductList = memo(function ProductList({ products }) {
  console.log("render ProductList");
  return (
    <ul>
      {products.map((p) => (
        <li key={p}>{p}</li>
      ))}
    </ul>
  );
});

const products = ["Coffee", "Tea", "Bagel"];

export default function App() {
  const [note, setNote] = useState("");
  return (
    <>
      <input value={note} onChange={(e) => setNote(e.target.value)} placeholder="Order note" />
      <ProductList products={products} />
    </>
  );
}
```

<Concept name="The catch: new objects and functions every render" id="identity">

`products` above is defined **outside** the component, so it's the same array every time. But objects, arrays and functions created **inside** a component are **new on every render**, and a new value is never `Object.is`-equal to the old one, even with the same contents. That silently breaks `memo`:

<Compare
  wrong="A new array and a new function every render: memo compares, sees changes, renders anyway"
  right="useMemo and useCallback keep the same values between renders"
  wrongFile="App.jsx"
  rightFile="App.jsx"
>

```jsx
function App() {
  const [note, setNote] = useState("");
  const hot = products.filter((p) => p.hot);
  return (
    <ProductList
      products={hot}
      onAdd={(p) => addToCart(p)}
    />
  );
}
```

```jsx
function App() {
  const [note, setNote] = useState("");
  const hot = useMemo(() => products.filter((p) => p.hot), []);
  const handleAdd = useCallback((p) => addToCart(p), []);
  return (
    <ProductList
      products={hot}
      onAdd={handleAdd}
    />
  );
}
```

</Compare>

- **`useMemo(fn, deps)`** runs `fn` and caches the **result**; it only runs `fn` again when something in `deps` changes. Use it for expensive calculations and for objects or arrays passed to memoized children.
- **`useCallback(fn, deps)`** caches the **function itself**: `useCallback(fn, deps)` is the same as `useMemo(() => fn, deps)`.
- The **dependency array** lists every value from the component that `fn` uses. Leave one out and you get stale values; the ESLint rule `react-hooks/exhaustive-deps` checks it for you.

</Concept>

<Concept name="When to bother" id="when">

Memoization has a cost: extra code, extra comparisons and memory, and bugs from wrong dependency arrays. Reach for it when you've **measured** a slow render (the React DevTools Profiler shows which components render and how long they take), typically:

- a big list or table that re-renders on every keystroke elsewhere,
- an expensive calculation (sorting or filtering thousands of items),
- a value passed to a memoized child or used as an effect dependency.

Often a better fix is **structural**: move the fast-changing state down into a smaller component (here, an `OrderNote` component that owns `note`), so the slow part isn't below it at all.

</Concept>

<HowItWorks title="Object.is and why {} !== {}">

React compares props, state and dependencies with `Object.is(a, b)`, which is like `===`. For numbers and strings that compares values, but for objects, arrays and functions it compares **identity**: are they the very same thing in memory?

`{ a: 1 } === { a: 1 }` is `false`: two separate objects that happen to look alike. Every render runs your component function from the top, so every `{}`, `[]` and `() => {}` written inside it is brand new. `useMemo`, `useCallback` and `useState` are the ways to keep the **same** one across renders.

</HowItWorks>

<GoDeeper title="The React Compiler">

The **React Compiler** (a build-time plugin, stable since React 19) analyzes your components and inserts the memoization for you: it caches JSX, objects and callbacks automatically, as if you'd written `memo`, `useMemo` and `useCallback` everywhere they help. In projects that use it, you rarely write these by hand.

It relies on your components following the rules of React (pure render, no mutating props or state), which is one more reason those rules matter. You still need to understand identity and memoization to read existing code and debug performance.

</GoDeeper>

Typing in the note re-renders `ProductList` on every keystroke. Make it render **only** when its props really change: memoize the component, and give it a stable `onAdd`. Leave the `renders` counter in place; the tests use it to count renders.

```jsx starter file=/ProductList.js
export const renders = { count: 0 };

function ProductList({ products, onAdd }) {
  renders.count++;
  return (
    <ul>
      {products.map((p) => (
        <li key={p}>
          {p} <button onClick={() => onAdd(p)}>Add {p}</button>
        </li>
      ))}
    </ul>
  );
}

export default ProductList;
```

```jsx starter file=/App.js
import { useState } from "react";
import ProductList from "./ProductList";

const products = ["Coffee", "Tea"];

export default function App() {
  const [note, setNote] = useState("");
  const [cart, setCart] = useState([]);

  return (
    <>
      <input aria-label="Order note" value={note} onChange={(e) => setNote(e.target.value)} />
      <p>Cart: {cart.length}</p>
      <ProductList products={products} onAdd={(name) => setCart([...cart, name])} />
    </>
  );
}
```

```jsx tests file=/App.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";
import { renders } from "./ProductList";

test("typing in the note doesn't re-render ProductList", () => {
  render(<App />);
  const before = renders.count;
  fireEvent.change(screen.getByLabelText("Order note"), { target: { value: "h" } });
  fireEvent.change(screen.getByLabelText("Order note"), { target: { value: "hi" } });
  expect(renders.count).toBe(before);
});

test("adding still works, every time", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "Add Coffee" }));
  fireEvent.click(screen.getByRole("button", { name: "Add Tea" }));
  expect(screen.getByText("Cart: 2")).toBeInTheDocument();
});
```

```jsx solution file=/ProductList.js
import { memo } from "react";

export const renders = { count: 0 };

function ProductList({ products, onAdd }) {
  renders.count++;
  return (
    <ul>
      {products.map((p) => (
        <li key={p}>
          {p} <button onClick={() => onAdd(p)}>Add {p}</button>
        </li>
      ))}
    </ul>
  );
}

export default memo(ProductList);
```

```jsx solution file=/App.js
import { useCallback, useState } from "react";
import ProductList from "./ProductList";

const products = ["Coffee", "Tea"];

export default function App() {
  const [note, setNote] = useState("");
  const [cart, setCart] = useState([]);
  const handleAdd = useCallback((name) => setCart((c) => [...c, name]), []);

  return (
    <>
      <input aria-label="Order note" value={note} onChange={(e) => setNote(e.target.value)} />
      <p>Cart: {cart.length}</p>
      <ProductList products={products} onAdd={handleAdd} />
    </>
  );
}
```
