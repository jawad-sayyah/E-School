Sooner or later you'll add a `console.log` to a component and see it **twice**. That's not a bug: it's `<StrictMode>`, a development-only helper that most React projects (including Vite's starter and these sandboxes) turn on in `main.jsx`:

```jsx file=main.jsx
createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

<Concept name="What StrictMode does" id="what-it-does">

In **development only**, StrictMode:

1. **Renders every component twice** (and calls `useState`/`useMemo` initializers and updater functions twice), throwing away one result.
2. **Runs every effect twice on mount**: setup, then cleanup, then setup again, as if the component was mounted, unmounted and mounted again.
3. **Warns about deprecated APIs** in the console.

None of this happens in a production build. Open the console and watch:

<ReactPlayground height={300} console>

```jsx file=/App.js
import { useEffect, useState } from "react";

let renders = 0;

export default function App() {
  const [qty, setQty] = useState(1);
  renders++; // impure on purpose: counts calls to App
  console.log("render, call #" + renders);

  useEffect(() => {
    console.log("effect: connect to the stock feed");
    return () => console.log("cleanup: disconnect");
  }, []);

  return <button onClick={() => setQty(qty + 1)}>Quantity: {qty}</button>;
}
```

</ReactPlayground>

On load you'll see two renders, then *connect → disconnect → connect*. Each click logs two more renders.

</Concept>

<Concept name="Why: catching impure renders" id="impure">

A component's render must be **pure**: same props and state in, same JSX out, and nothing outside changed. If rendering twice changes the result, your render isn't pure, and in real apps React may render more than once (for transitions, Suspense, or rendering in the background) and show inconsistent UI.

<Compare
  wrong="Pushes into an array that lives outside the component: each render adds more"
  right="Builds a new array during render: rendering twice gives the same result"
  wrongFile="Receipt.jsx"
  rightFile="Receipt.jsx"
>

```jsx
const lines = [];
function Receipt({ items }) {
  items.forEach((i) => lines.push(<li key={i.id}>{i.name}</li>));
  return <ul>{lines}</ul>;
}
```

```jsx
function Receipt({ items }) {
  const lines = items.map((i) => <li key={i.id}>{i.name}</li>);
  return <ul>{lines}</ul>;
}
```

</Compare>

With StrictMode, the wrong version shows every item twice right away in development, so you find the bug at your desk instead of in production.

</Concept>

<Concept name="Why: catching missing cleanup" id="cleanup">

Running effects twice simulates a component being **mounted, removed and mounted again** (which really happens: navigating away and back, or React restoring hidden UI). If an effect starts something, it must stop it in its cleanup, or you get duplicate subscriptions, timers and listeners.

```jsx file=StockTicker.jsx
useEffect(() => {
  const id = setInterval(refreshStock, 5000);
  return () => clearInterval(id);   // without this, StrictMode reveals two intervals
}, []);
```

If your app behaves correctly with StrictMode's setup → cleanup → setup, it will behave correctly when components really unmount and remount. The Hooks course goes deep on effects and cleanup.

</Concept>

<HowItWorks title="Should I turn it off to get rid of the double logs?">

No. The double calls are the point: they make bugs that would show up rarely and randomly show up **every time**, in development, where they're cheap to fix. The cost is a few extra logs. If a log is confusing, React DevTools greys out the second one, and remember that production runs everything once.

</HowItWorks>
