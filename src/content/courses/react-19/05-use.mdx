`use` is an unusual API: it reads the value of a **resource**, a promise or a context, during render. With a promise, the component **suspends** until it resolves, so the nearest `<Suspense>` shows its fallback in the meantime. Unlike hooks, `use` can be called inside conditions and loops.

<Concept name="use(promise)" id="use-promise">

<ReactPlayground height={360}>

```jsx file=/App.js
import { Suspense, use, useState } from "react";
import { fetchReviews } from "./api";

function Reviews({ reviewsPromise }) {
  const reviews = use(reviewsPromise); // suspends until the promise resolves
  return (
    <ul>
      {reviews.map((r) => (
        <li key={r.id}>{"★".repeat(r.stars)} {r.text}</li>
      ))}
    </ul>
  );
}

export default function App() {
  const [reviewsPromise, setReviewsPromise] = useState(null);
  return (
    <>
      <h2>Coffee</h2>
      <button onClick={() => setReviewsPromise(fetchReviews("coffee"))}>Load reviews</button>
      {reviewsPromise && (
        <Suspense fallback={<p>Loading reviews…</p>}>
          <Reviews reviewsPromise={reviewsPromise} />
        </Suspense>
      )}
    </>
  );
}
```

```js file=/api.js
export function fetchReviews(product) {
  return new Promise((resolve) =>
    setTimeout(
      () => resolve([
        { id: 1, stars: 5, text: "Best in town" },
        { id: 2, stars: 4, text: "Great, but the line is long" },
      ]),
      1000,
    ),
  );
}
```

</ReactPlayground>

- The **promise is created outside** the component that reads it: in an event handler here, or by a framework or data library. A promise created during render would be a new promise on every render, and `use` would suspend forever.
- While pending, the nearest `<Suspense>` shows its fallback.
- If the promise **rejects**, the nearest **error boundary** shows its fallback.

</Concept>

<Concept name="use(context)" id="use-context">

`use(SomeContext)` does what `useContext(SomeContext)` does, but because `use` isn't bound by the Rules of Hooks' "no conditions" rule, it can be read after an early return or inside an `if`:

```jsx file=Price.jsx
function Price({ amount, showCurrency }) {
  if (!showCurrency) return <span>{amount.toFixed(2)}</span>;
  const currency = use(CurrencyContext); // fine: use can be conditional
  return <span>{currency.symbol}{amount.toFixed(2)}</span>;
}
```

It must still be called during render of a component or hook, not in an event handler or effect, and not inside `try`/`catch`.

</Concept>

<HowItWorks title="How use suspends">

When `use(promise)` sees a pending promise, it throws a special signal that React catches: "this component is waiting". React shows the nearest Suspense fallback and attaches a callback to the promise. When it settles, React renders the component again; this time `use` finds the value already attached to the promise and returns it (or throws the error for the error boundary). That's why the **same** promise object must be passed on every render: React stores the result on it.

</HowItWorks>

<GoDeeper title="Where promises come from in real apps">

Creating and caching promises correctly (one per request, reused between renders, refetched when needed) is hard, which is why you'll mostly meet `use` through:

- **Server Components** passing promises down to Client Components,
- **framework loaders** (React Router, Next.js),
- **data libraries** like TanStack Query (`useSuspenseQuery`).

You'll fetch data that way in the React Ecosystem course. Knowing how `use` + Suspense + error boundaries fit together makes those tools much less magical.

</GoDeeper>

`App` already creates the promise once (outside render). Make `Menu` read it with `use`, and show **Loading menu…** while it's pending.

```jsx starter file=/App.js
import { useState } from "react";
import { fetchMenu } from "./api";

function Menu({ menuPromise }) {
  const items = []; // read the promise here
  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default function App() {
  const [menuPromise] = useState(() => fetchMenu());
  return <Menu menuPromise={menuPromise} />;
}
```

```js starter file=/api.js
export function fetchMenu() {
  return new Promise((resolve) => setTimeout(() => resolve(["Coffee", "Tea", "Bagel"]), 100));
}
```

```jsx tests file=/App.test.js
import { act, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

// Rendering inside an async act lets React retry suspended components when their promise resolves
const renderApp = () => act(async () => {
  render(<App />);
});
const wait = (ms) => act(async () => {
  await new Promise((resolve) => setTimeout(resolve, ms));
});

test("shows a loading message while the menu loads", async () => {
  await renderApp();
  expect(screen.getByText("Loading menu…")).toBeInTheDocument();
});

test("shows the menu when the promise resolves", async () => {
  await renderApp();
  await wait(500);
  expect(screen.getByText("Bagel")).toBeInTheDocument();
  expect(screen.getAllByRole("listitem")).toHaveLength(3);
});
```

```jsx solution file=/App.js
import { Suspense, use, useState } from "react";
import { fetchMenu } from "./api";

function Menu({ menuPromise }) {
  const items = use(menuPromise);
  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default function App() {
  const [menuPromise] = useState(() => fetchMenu());
  return (
    <Suspense fallback={<p>Loading menu…</p>}>
      <Menu menuPromise={menuPromise} />
    </Suspense>
  );
}
```
