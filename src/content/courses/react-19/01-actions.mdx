Almost every app does this dance: the user clicks Save, you show "Saving…", call the server, then show the result or an error, and you make sure a double-click doesn't send twice. React 19 builds that into **Actions**: async functions run inside a transition.

<Concept name="Before: managing pending state by hand" id="before">

```jsx file=SaveName.jsx
function SaveName() {
  const [name, setName] = useState("");
  const [isSaving, setIsSaving] = useState(false);
  const [error, setError] = useState(null);

  async function handleSave() {
    setIsSaving(true);
    const err = await updateName(name);
    setIsSaving(false);
    if (err) setError(err);
  }
  // …
}
```

Three pieces of state, and it's easy to forget to reset one (an early `return`, an exception…).

</Concept>

<Concept name="After: an async transition" id="after">

In React 19, `startTransition` accepts an **async** function. Everything inside is an **Action**, and `isPending` is true from the moment it starts until it finishes, including the awaits.

<ReactPlayground height={360}>

```jsx file=/App.js
import { useState, useTransition } from "react";
import { updateName } from "./api";

export default function App() {
  const [name, setName] = useState("");
  const [saved, setSaved] = useState("");
  const [error, setError] = useState(null);
  const [isPending, startTransition] = useTransition();

  function handleSave() {
    startTransition(async () => {
      const err = await updateName(name);
      if (err) {
        setError(err);
        return;
      }
      setError(null);
      setSaved(name);
    });
  }

  return (
    <>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name on the cup" />
      <button onClick={handleSave} disabled={isPending}>
        {isPending ? "Saving…" : "Save"}
      </button>
      {error && <p className="error">{error}</p>}
      {saved && <p>Saved: {saved}</p>}
    </>
  );
}
```

```js file=/api.js
// A fake server: takes a second, rejects empty names
export function updateName(name) {
  return new Promise((resolve) =>
    setTimeout(() => resolve(name.trim() ? null : "Please enter a name."), 1000),
  );
}
```

```css file=/styles.css
body { font-family: system-ui, sans-serif; padding: 16px; }
.error { color: #c0392b; }
input { padding: 6px; margin-right: 8px; }
```

</ReactPlayground>

- No `isSaving` state: `isPending` covers it, from the first line of the Action to the last.
- The button is disabled while pending, so double-clicks can't send twice.
- One caveat: state updates made **after an `await`** aren't automatically marked as part of the transition (a JavaScript limitation React plans to lift with AsyncContext). They still apply, and `isPending` still covers the whole function. If those later updates must be transitions too (for example, so they don't show a Suspense fallback), wrap them in another `startTransition`.

</Concept>

<Concept name="What counts as an Action" id="what-is-action">

By convention, a function that starts a transition is called an Action, and props that accept one are named `action` or end in `Action` (`submitAction`, `onSaveAction`). React 19 builds several features on top of Actions:

| Feature | What it adds |
| --- | --- |
| `<form action={fn}>` | the form calls `fn(formData)` as an Action on submit |
| `useActionState` | the Action's result as state, plus `isPending` |
| `useFormStatus` | the parent form's pending state, readable from a child |
| `useOptimistic` | show the expected result instantly while the Action runs |

The next lessons take them one at a time.

</Concept>

<HowItWorks title="Why a transition?">

Transitions were built for non-urgent updates that React can render in the background (the Hooks course). An async request is the same idea stretched over time: the UI should stay responsive, show the old content (perhaps dimmed) until the new content is ready, and know when it's pending. Making the whole async function a transition gives all of that, plus **ordering**: when several Actions finish, React applies their updates in sequence, and `isPending` stays true until the last one is done.

</HowItWorks>

Make **Save** use an async transition: while `saveNote` is running, the button must say **Saving…** and be disabled; when it finishes, show **Saved: …** with the note. Don't add any new `useState` for the pending state.

```jsx starter file=/App.js
import { useState } from "react";
import { saveNote } from "./api";

export default function App() {
  const [note, setNote] = useState("");
  const [saved, setSaved] = useState("");

  async function handleSave() {
    await saveNote(note);
    setSaved(note);
  }

  return (
    <>
      <label>
        Note <input value={note} onChange={(e) => setNote(e.target.value)} />
      </label>
      <button onClick={handleSave}>Save</button>
      {saved && <p>Saved: {saved}</p>}
    </>
  );
}
```

```js starter file=/api.js
export function saveNote(note) {
  return new Promise((resolve) => setTimeout(resolve, 200));
}
```

```jsx tests file=/App.test.js
import { act, fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

const wait = (ms) => act(async () => {
  await new Promise((resolve) => setTimeout(resolve, ms));
});

test("shows Saving… and disables the button while saving", async () => {
  render(<App />);
  fireEvent.change(screen.getByLabelText("Note"), { target: { value: "Oat milk" } });
  fireEvent.click(screen.getByRole("button", { name: "Save" }));
  await wait(50);
  const button = screen.getByRole("button", { name: "Saving…" });
  expect(button).toBeDisabled();
  await wait(300);
});

test("shows the saved note when done", async () => {
  render(<App />);
  fireEvent.change(screen.getByLabelText("Note"), { target: { value: "Oat milk" } });
  fireEvent.click(screen.getByRole("button", { name: "Save" }));
  await wait(300);
  expect(screen.getByText("Saved: Oat milk")).toBeInTheDocument();
  expect(screen.getByRole("button", { name: "Save" })).toBeEnabled();
});
```

```jsx solution file=/App.js
import { useState, useTransition } from "react";
import { saveNote } from "./api";

export default function App() {
  const [note, setNote] = useState("");
  const [saved, setSaved] = useState("");
  const [isPending, startTransition] = useTransition();

  function handleSave() {
    startTransition(async () => {
      await saveNote(note);
      setSaved(note);
    });
  }

  return (
    <>
      <label>
        Note <input value={note} onChange={(e) => setNote(e.target.value)} />
      </label>
      <button onClick={handleSave} disabled={isPending}>
        {isPending ? "Saving…" : "Save"}
      </button>
      {saved && <p>Saved: {saved}</p>}
    </>
  );
}
```
