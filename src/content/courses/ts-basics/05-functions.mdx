Functions are where types help most: a function's signature is a promise about what it takes and what it gives back, checked at every call.

<Concept name="Parameters and return types" id="params">

<TSPlayground file="totals.ts" errors={[6, 7]} expected={["8", "8.8"]}>

```ts
function lineTotal(price: number, qty: number): number {
  return price * qty;
}

console.log(lineTotal(4, 2));
lineTotal(4);              // error: expected 2 arguments
lineTotal(4, "2");         // error: "2" isn't a number

const withTax = (amount: number, rate = 0.1): number => amount * (1 + rate);
console.log(withTax(8).toFixed(1));
```

</TSPlayground>

- **Parameters always need types** (TypeScript can't know what callers will pass). In strict mode a missing one is an error: "implicitly has an any type".
- **Return types** can be inferred, but writing them on exported functions documents intent and catches a wrong `return` early.
- `rate = 0.1` is a **default parameter**: its type (`number`) is inferred from the default, and callers may leave it out.

</Concept>

<Concept name="Optional and rest parameters" id="optional-rest">

```ts file=greet.ts
function greet(name: string, title?: string): string {   // title: string | undefined
  return title ? `Hello, ${title} ${name}` : `Hello, ${name}`;
}

function sum(...prices: number[]): number {              // any number of numbers
  return prices.reduce((a, b) => a + b, 0);
}

greet("Ada");
greet("Ada", "Dr.");
sum(4, 3, 2.5);
```

Optional parameters (`?`) must come after required ones.

</Concept>

<Concept name="Function types and callbacks" id="callbacks">

A function's type is written like an arrow: `(price: number) => string`. Use it for callbacks and for props like `onAdd`:

<TSPlayground file="callbacks.ts" errors={[9]} expected={["[ '$4.00', '$2.50' ]", "Coffee", "Added Coffee"]}>

```ts
type Formatter = (price: number) => string;

const dollars: Formatter = (p) => `$${p.toFixed(2)}`;   // p is inferred as number
console.log([4, 2.5].map(dollars));

function onAdd(callback: (name: string) => void) {
  callback("Coffee");
}
onAdd((name: number) => console.log(name));               // error: wrong parameter type
onAdd((name) => console.log(`Added ${name}`));
```

</TSPlayground>

When a function is passed where a function type is expected, its parameters are inferred from that type (**contextual typing**), so you rarely annotate callback parameters.

</Concept>

<Concept name="void and never" id="void-never">

- **`void`**: the function doesn't return anything useful (`console.log`, event handlers).
- **`never`**: the function never returns at all, because it always throws or loops forever. It's also the type of "impossible" leftover cases, which the In Depth course uses for exhaustive checks.

```ts file=errors.ts
function logOrder(id: number): void {
  console.log("Order", id);
}

function fail(message: string): never {
  throw new Error(message);
}
```

</Concept>

<HowItWorks title="Why parameter types matter so much">

Inside a function, TypeScript can only check your code if it knows what the parameters are. Outside, every **call** is checked against the parameters. So typing one line, the signature, protects both the function body and every place in the codebase that calls it. That's why "type your function signatures" is the first rule of TypeScript, and why inference is enough for most local variables.

</HowItWorks>

<TSExercise
  id="format-price"
  title="A typed formatPrice"
  hints={[
    "Signature: `function formatPrice(amount: number, currency = \"$\", decimals?: number): string`.",
    "Use `amount.toFixed(decimals ?? 2)`.",
  ]}
>

Write `formatPrice(amount, currency, decimals)`: `amount` is a number; `currency` is text and defaults to `"$"`; `decimals` is optional (use 2 when it's missing). It returns a string like `$4.00`.

```ts starter
function formatPrice(amount, currency, decimals) {
  return currency + amount;
}
```

```ts types
const a: string = formatPrice(4);
const b: string = formatPrice(4, "€");
const c: string = formatPrice(4, "€", 0);
// @ts-expect-error the amount must be a number
formatPrice("4");
// @ts-expect-error decimals must be a number
formatPrice(4, "$", "2");
```

```js tests
test("defaults to dollars and two decimals", () => {
  expect(formatPrice(4)).toBe("$4.00");
});

test("uses the currency and decimals given", () => {
  expect(formatPrice(4.5, "€")).toBe("€4.50");
  expect(formatPrice(4.5, "€", 0)).toBe("€5");
});
```

```ts solution
function formatPrice(amount: number, currency = "$", decimals?: number): string {
  return currency + amount.toFixed(decimals ?? 2);
}
```

</TSExercise>
