A **type** describes what kind of value something can hold. You write it after a colon: `let name: string`. Most of the time you don't even need to: TypeScript **infers** the type from the value.

<Concept name="The primitive types" id="primitives">

<TSPlayground file="types.ts" errors={[8]} expected={["Coffee 4 true"]}>

```ts
let name: string = "Coffee";
let price: number = 4;          // whole numbers and decimals are both number
let inStock: boolean = true;

console.log(name, price, inStock);

price = 4.5;                    // fine: still a number
price = "four";                 // error: a string isn't a number
```

</TSPlayground>

Once a variable has a type, TypeScript makes sure every value you put in it matches. Hover over any variable in the editor to see its type.

</Concept>

<Concept name="Inference: let TypeScript work it out" id="inference">

You rarely need to annotate a variable you initialize right away. TypeScript reads the value and **infers** the type:

<TSPlayground file="inference.ts" errors={[5]} expected={["5 3 Iced coffee"]}>

```ts
let qty = 2;                 // inferred: number
const label = "Iced coffee"; // inferred: the literal type "Iced coffee" (a const can't change)

function oops() {
  qty = "three";             // error: qty is a number
}

qty = qty + 3;
const total = qty * 0.6;     // inferred: number
console.log(qty, Math.round(total), label);
```

</TSPlayground>

**Rule of thumb:** let TypeScript infer variables; write types on **function parameters** (TypeScript can't guess what callers will pass) and on things exported for others to use.

</Concept>

<Concept name="any, unknown, null and undefined" id="special">

- **`any`** turns type checking off for that value. Anything goes, so every bug is back. Avoid it; in strict projects it's often banned by lint.
- **`unknown`** means "some value, but I don't know what yet". You must check what it is before using it, so it's the safe choice for data from outside (JSON, user input).
- **`null`** and **`undefined`** are their own types. With `strict` on (always, in real projects), a `string` can't be `null`: you write `string | null` when it can (next lessons).

<TSPlayground file="unknown.ts" errors={[3]} expected={["COFFEE"]}>

```ts
const fromServer: unknown = JSON.parse('"coffee"');

fromServer.toUpperCase();          // error: check what it is first

if (typeof fromServer === "string") {
  console.log(fromServer.toUpperCase()); // fine: now TypeScript knows it's a string
}
```

</TSPlayground>

With `any` instead of `unknown`, the bad call on line 3 would compile without a word, and a call like `value.toFixed(2)` on a string would crash at run time instead.

</Concept>

<HowItWorks title="Where types come from">

TypeScript builds a type for every expression. Literals have types (`4` is a `number`, `"Tea"` is a `string`), operators produce types (`number * number` is a `number`), and functions have return types. When you annotate, TypeScript checks the value against your annotation; when you don't, it uses what it worked out. For `const`, it keeps the exact value as a **literal type** (`"Iced coffee"`), because a `const` can never change. That detail powers union types two lessons from now.

</HowItWorks>

<TSExercise
  id="annotate-product"
  title="Type the product variables"
  hints={[
    "Write the type after the name: `let stock: number = 12;`",
    "The discount code can be missing, so its type is `string | null`.",
  ]}
>

Add type annotations so that each variable only accepts the right kind of value: `productName` is text, `stock` is a number, `onSale` is true/false, and `discountCode` is text **or** `null` (no code).

```ts starter
let productName = "Coffee";
let stock = 12;
let onSale = false;
let discountCode = null;
```

```ts types
// a discount code can be set later
discountCode = "SAVE10";
// @ts-expect-error stock must be a number
stock = "twelve";
// @ts-expect-error onSale must be a boolean
onSale = "no";
// @ts-expect-error a discount code is text, not a number
discountCode = 10;
```

```ts solution
let productName: string = "Coffee";
let stock: number = 12;
let onSale: boolean = false;
let discountCode: string | null = null;
```

</TSExercise>
