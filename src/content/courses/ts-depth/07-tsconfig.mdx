Every TypeScript project has a `tsconfig.json` at its root. It tells the compiler **which files** to check and **how strictly**. You'll rarely write one from scratch (Vite and other tools generate it), but you'll read and tweak it often.

<Concept name="A typical Vite + React config" id="typical">

```json file=tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedIndexedAccess": true,
    "noEmit": true,
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src"]
}
```

| Option | What it means |
| --- | --- |
| `target` | which JavaScript version to output (and assume) |
| `lib` | which built-in APIs exist: `DOM` for browsers, `ES2022` for modern JS |
| `module` / `moduleResolution` | how `import` works; `bundler` matches Vite and other bundlers |
| `jsx: "react-jsx"` | `.tsx` files use React's automatic JSX runtime |
| `strict` | turns on the whole family of strict checks (always on!) |
| `noEmit` | only type-check; the bundler (Vite) produces the JavaScript |
| `paths` | import aliases like `@/components/Button` |
| `include` | which files belong to the project |

</Concept>

<Concept name="What strict turns on" id="strict">

`"strict": true` is a shortcut for several checks. The two you'll feel most:

- **`noImplicitAny`**: a parameter or variable whose type can't be inferred is an error, instead of silently becoming `any`.
- **`strictNullChecks`**: `null` and `undefined` aren't part of every type. A `string` is never `null`; you must write `string | null` and handle it.

Plus `strictFunctionTypes`, `strictPropertyInitialization`, `useUnknownInCatchVariables` (`catch (e)` gives `unknown`) and a few more. All examples in this school run with `strict` on: that's how real projects are set up.

</Concept>

<Concept name="Extra checks worth turning on" id="extra">

- **`noUncheckedIndexedAccess`**: `items[0]` and `record[key]` include `undefined`, because the item might not be there.
- **`noUnusedLocals` / `noUnusedParameters`**: flags dead code.
- **`noFallthroughCasesInSwitch`**: a `case` without `break`/`return` is an error.
- **`exactOptionalPropertyTypes`**: `note?: string` can be missing, but not explicitly `undefined`.
- **`verbatimModuleSyntax`**: type-only imports must say `import type`, so tools can strip them safely.

</Concept>

<HowItWorks title="Who reads tsconfig.json?">

Three different tools: your **editor** (for squiggles and autocomplete), **`tsc`** (the command-line checker, run in CI with `tsc --noEmit` or `tsc -b`), and your **bundler** (Vite strips types itself with a fast transpiler that doesn't type-check, but reads `paths` through a plugin or its own config). That's why a project can build successfully while `tsc` reports errors: type-checking is a separate step, so make sure it runs in CI.

</HowItWorks>
