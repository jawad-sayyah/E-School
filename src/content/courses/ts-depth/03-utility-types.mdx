TypeScript ships a toolbox of **utility types**: generic types that take a type and return a changed version of it. They keep variations of a type (a form's draft, an update payload, a public view) in sync with the original.

<Concept name="Changing properties: Partial, Required, Readonly" id="modifiers">

<TSPlayground file="partial.ts" errors={[13]} expected={["{ id: 1, name: 'Coffee', price: 4.5, stock: 10 }"]}>

```ts
type Product = { id: number; name: string; price: number; stock: number };

// An update can change any subset of fields
function update(product: Product, changes: Partial<Product>): Product {
  return { ...product, ...changes };
}

const coffee: Product = { id: 1, name: "Coffee", price: 4, stock: 10 };
const updated = update(coffee, { price: 4.5 });
console.log(updated);

const frozen: Readonly<Product> = updated;
frozen.price = 1;                      // error: every property is readonly
```

</TSPlayground>

- `Partial<T>`: every property optional. Perfect for "patch" updates and form drafts.
- `Required<T>`: every property required (removes `?`).
- `Readonly<T>`: every property readonly.

</Concept>

<Concept name="Choosing properties: Pick and Omit" id="pick-omit">

```ts file=user.ts
type User = { id: number; name: string; email: string; passwordHash: string };

type PublicUser = Omit<User, "passwordHash">;     // everything except the hash
type UserPreview = Pick<User, "id" | "name">;     // only id and name
type NewUser = Omit<User, "id">;                  // the server assigns the id
```

</Concept>

<Concept name="Record: an object with known keys" id="record">

`Record<K, V>` is an object type whose keys are `K` and whose values are `V`. With a union of keys, TypeScript makes sure **every** key is present:

```ts file=stock.ts
type Size = "small" | "medium" | "large";
const stock: Record<Size, number> = { small: 10, medium: 4, large: 0 }; // a missing size is an error
const notes: Record<string, string> = {};                                 // any string key
```

</Concept>

<Concept name="Types from functions and promises" id="function-utils">

```ts file=api.ts
async function fetchProduct(id: number) {
  return { id, name: "Coffee", price: 4 };
}

type FetchParams = Parameters<typeof fetchProduct>;      // [id: number]
type FetchResult = ReturnType<typeof fetchProduct>;      // Promise<{ id: number; name: string; price: number }>
type ProductData = Awaited<ReturnType<typeof fetchProduct>>; // { id: number; name: string; price: number }

type MaybeName = string | null | undefined;
type Name = NonNullable<MaybeName>;                      // string
```

These let you derive types from code you don't control (a library's function) instead of copying its types by hand.

</Concept>

<HowItWorks title="Utility types are just generics">

None of these are magic; they're generic types written with the tools from the previous lessons:

```ts file=lib.d.ts
type Partial<T> = { [K in keyof T]?: T[K] };
type Readonly<T> = { readonly [K in keyof T]: T[K] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Record<K extends keyof any, V> = { [P in K]: V };
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
```

Mapped types, `keyof` and indexed access: once you can read these, you can write your own.

</HowItWorks>

<TSExercise

  title="Derive the form types"
  hints={[

Derive three types from `Product` and `Size` instead of writing them by hand: `NewProduct` (everything but `id`), `ProductPatch` (any subset of the fields except `id`), and `StockBySize` (a number for every size).

```ts starter
type Size = "small" | "medium" | "large";
type Product = { id: number; name: string; price: number; size: Size };

type NewProduct = any;
type ProductPatch = any;
type StockBySize = any;
```

```ts types
const draft: NewProduct = { name: "Tea", price: 2, size: "small" };
const patch: ProductPatch = { price: 2.5 };
const empty: ProductPatch = {};
const stock: StockBySize = { small: 1, medium: 2, large: 0 };
// @ts-expect-error a new product has no id yet
const withId: NewProduct = { id: 1, name: "Tea", price: 2, size: "small" };
// @ts-expect-error a new product needs a name
const noName: NewProduct = { price: 2, size: "small" };
// @ts-expect-error the id can't be patched
const badPatch: ProductPatch = { id: 9 };
// @ts-expect-error every size needs a number
const partialStock: StockBySize = { small: 1 };
```

```ts solution
type Size = "small" | "medium" | "large";
type Product = { id: number; name: string; price: number; size: Size };

type NewProduct = Omit<Product, "id">;
type ProductPatch = Partial<Omit<Product, "id">>;
type StockBySize = Record<Size, number>;
```
