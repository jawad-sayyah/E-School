You've already used generics: `Array<number>` is the generic `Array` type with `number` plugged in. A **generic** is a type or function with a **type parameter**, a placeholder like `T` that's filled in when it's used. It lets one piece of code work for many types without falling back to `any`.

<Concept name="The problem: any loses the type" id="problem">

<TSPlayground file="first.ts" errors={[11]} expected={["Coffee 4"]}>

```ts
function firstAny(list: any[]): any {
  return list[0];
}

function first<T>(list: T[]): T | undefined {
  return list[0];
}

const name = firstAny(["Coffee", "Tea"]);   // any: no help from here on
const price = first([4, 2]);                 // number | undefined
const shout: string = first([4, 2]);          // error: it's a number, not a string

console.log(name, price);
```

</TSPlayground>

`first<T>` says: "whatever type the array's items have, I return that same type". TypeScript **infers** `T` from the argument (`number` here), so you rarely write `first<number>(...)` yourself.

</Concept>

<Concept name="Generic types" id="generic-types">

Types can have parameters too:

```ts file=api.ts
type ApiResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string };

type Box<T> = { value: T; updatedAt: Date };

const products: ApiResult<string[]> = { ok: true, data: ["Coffee", "Tea"] };
const failed: ApiResult<number> = { ok: false, error: "Server down" };
```

You'll see this pattern everywhere: `Promise<T>`, `Array<T>`, `Map<K, V>`, React's `useState<T>`, TanStack Query's `useQuery<TData>`.

</Concept>

<Concept name="Constraints: T extends …" id="constraints">

Sometimes `T` can't be just anything. `extends` sets a **minimum shape**:

<TSPlayground file="constraints.ts" errors={[11]} expected={["Tea", "10"]}>

```ts
function byId<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id);   // item.id is allowed: every T has an id
}

function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

const menu = [{ id: 1, name: "Coffee" }, { id: 2, name: "Tea" }];
console.log(byId(menu, 2)?.name);                  // T is { id: number; name: string }
byId([{ name: "Cake" }], 1);                        // error: no id
console.log(longest("cappuccino", "tea").length);  // works for strings, arrays…
```

</TSPlayground>

The result keeps the **full** type (`name` is still there), unlike a parameter typed as `{ id: number }[]`, which would forget everything but `id`.

</Concept>

<Concept name="Several parameters, and defaults" id="defaults">

```ts file=pairs.ts
function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}
const p = pair("Coffee", 4);                 // [string, number]

type Paged<T, Meta = { page: number }> = { items: T[]; meta: Meta };
const page: Paged<string> = { items: ["Tea"], meta: { page: 1 } };   // Meta uses the default
```

Name type parameters `T` for one, or meaningful names (`TItem`, `TData`) when there are several.

</Concept>

<HowItWorks title="How TypeScript infers T">

When you call `first([4, 2])`, TypeScript matches the argument's type (`number[]`) against the parameter's type (`T[]`) and solves `T = number`. Then it substitutes `T` everywhere in the signature, so the return type becomes `number | undefined`. If the arguments give conflicting answers, or there's nothing to infer from (a generic function with no parameters using `T`), you pass it explicitly: `useState<CartLine[]>([])`.

</HowItWorks>

<TSExercise
  id="generic-group-by"
  title="A generic groupBy"
  hints={[
    "Two type parameters: the item type and the key: `function groupBy<T, K extends string>(items: T[], getKey: (item: T) => K): Record<K, T[]>`.",
    "Start with `const groups = {} as Record<K, T[]>;` and push each item into `groups[key] ??= []`.",
  ]}
>

Write a generic `groupBy(items, getKey)` that groups items into an object of arrays by the string key `getKey` returns. The result must keep the items' full type.

```ts starter
function groupBy(items: any[], getKey: (item: any) => string): any {
  return {};
}
```

```ts types
const menu = [
  { name: "Coffee", kind: "hot" as const, price: 4 },
  { name: "Lemonade", kind: "cold" as const, price: 3 },
];
const groups = groupBy(menu, (m) => m.kind);
// the groups keep the full item type
const firstHotPrice: number | undefined = groups.hot[0]?.price;
// @ts-expect-error items have no "calories" property
groups.hot[0]?.calories;
// @ts-expect-error the key function must return a string
groupBy(menu, (m) => m.price);
```

```js tests
test("groups items by key", () => {
  const menu = [
    { name: "Coffee", kind: "hot" },
    { name: "Lemonade", kind: "cold" },
    { name: "Tea", kind: "hot" },
  ];
  const groups = groupBy(menu, (m) => m.kind);
  expect(groups.hot.map((m) => m.name)).toEqual(["Coffee", "Tea"]);
  expect(groups.cold.map((m) => m.name)).toEqual(["Lemonade"]);
});
```

```ts solution
function groupBy<T, K extends string>(items: T[], getKey: (item: T) => K): Record<K, T[]> {
  const groups = {} as Record<K, T[]>;
  for (const item of items) {
    const key = getKey(item);
    (groups[key] ??= []).push(item);
  }
  return groups;
}
```
