Mocking `fetch` with `vi.fn()` works, but it couples the test to *how* the component fetches (fetch vs. axios vs. TanStack Query, the exact call signature). **MSW** (Mock Service Worker) intercepts requests at the **network level** instead: the component runs its real fetching code, and MSW answers the HTTP request.

<Concept name="Handlers and a test server" id="setup">

```js file=src/mocks/handlers.js
import { http, HttpResponse } from "msw";

export const handlers = [
  http.get("/api/products", () =>
    HttpResponse.json([
      { id: 1, name: "Tea", price: 2 },
      { id: 2, name: "Coffee", price: 4 },
    ]),
  ),
];
```

```js file=src/test/setup.js
import { afterAll, afterEach, beforeAll } from "vitest";
import { setupServer } from "msw/node";
import { handlers } from "../mocks/handlers";

export const server = setupServer(...handlers);

beforeAll(() => server.listen({ onUnhandledRequest: "error" }));
afterEach(() => server.resetHandlers());   // undo per-test overrides
afterAll(() => server.close());
```

Register the setup file in `vitest.config` (`test.setupFiles`). `onUnhandledRequest: "error"` makes any request you forgot to mock fail loudly.

</Concept>

<Concept name="Testing every state" id="states">

```jsx file=ProductList.test.jsx
import { http, HttpResponse, delay } from "msw";
import { server } from "../test/setup";

test("shows the products", async () => {
  render(<ProductList />);
  expect(screen.getByText("Loading products…")).toBeInTheDocument();
  expect(await screen.findByText("Tea")).toBeInTheDocument();
});

test("shows an error when the server fails", async () => {
  server.use(http.get("/api/products", () => new HttpResponse(null, { status: 500 })));
  render(<ProductList />);
  expect(await screen.findByRole("alert")).toHaveTextContent("Couldn't load products");
});

test("shows a message for an empty catalog", async () => {
  server.use(http.get("/api/products", () => HttpResponse.json([])));
  render(<ProductList />);
  expect(await screen.findByText("No products yet.")).toBeInTheDocument();
});
```

`server.use(…)` overrides a handler for one test; `resetHandlers()` restores the defaults afterwards. The same handlers can run in the browser during development (`msw/browser`), so the UI works before the real API exists.

</Concept>

<HowItWorks title="Why mock at the network level?">

The test exercises everything the user depends on: the component, your fetching hook, TanStack Query's caching, JSON parsing, error handling. Swap fetch for axios, and the tests still pass. Mock functions are still the right tool when the component **takes** a function as a prop (dependency injection), as in the exercise below, and for non-network boundaries like timers.

</HowItWorks>

`ProductList` takes a `fetchProducts()` function (so tests can pass a mock, like an MSW handler would answer). It shows **Loading products…**, then the products, **No products yet.** for an empty list, or an alert **Couldn't load products.** if the request fails. Test every state.

```jsx code file=/ProductList.js
import { useEffect, useState } from "react";

export default function ProductList({ fetchProducts }) {
  const [state, setState] = useState({ status: "loading" });

  useEffect(() => {
    let ignore = false;
    fetchProducts().then(
      (products) => !ignore && setState({ status: "success", products }),
      () => !ignore && setState({ status: "error" }),
    );
    return () => {
      ignore = true;
    };
  }, [fetchProducts]);

  if (state.status === "loading") return <p>Loading products…</p>;
  if (state.status === "error") return <p role="alert">Couldn't load products.</p>;
  if (state.products.length === 0) return <p>No products yet.</p>;
  return (
    <ul>
      {state.products.map((p) => (
        <li key={p.id}>{p.name}</li>
      ))}
    </ul>
  );
}
```

import { render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import { expect, test, vi } from "vitest";
import ProductList from "./ProductList";

test("shows the products", async () => {
  render(<ProductList fetchProducts={vi.fn().mockResolvedValue([{ id: 1, name: "Tea" }])} />);

});

import { render, screen } from "@testing-library/react";
