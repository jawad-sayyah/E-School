A bad test is worse than no test: it costs time to maintain and gives false confidence. These are the mistakes reviewers flag most often.

<Concept name="Mistake 1: a test that can't fail" id="cant-fail" warn>

<Compare
  wrong="No real assertion: passes whatever total returns"
  right="Asserts the exact expected value"
  wrongFile="total.test.js"
  rightFile="total.test.js"
>

```js
test("calculates the total", () => {
  const total = getTotal(cart);
  expect(total).toBeTruthy();       // 11, 999 and "oops" all pass
});
```

```js
test("adds price × qty for every line", () => {
  expect(getTotal(cart)).toBe(11);
});
```

</Compare>

**Why:** `toBeTruthy`, `toBeDefined` and "it didn't throw" pass for almost any wrong answer. Assert the **specific** expected value, and when you write a test, break the code on purpose once to watch it fail.

</Concept>

<Concept name="Mistake 2: forgetting await" id="await" warn>

```js file=async.test.js
test("loads products", () => {
  expect(loadProducts()).resolves.toHaveLength(3);   // never awaited: always passes
});
test("shows the products", () => {
  render(<ProductList />);
  expect(screen.findByText("Tea")).toBeTruthy();      // a promise is truthy
});
```

**Why:** the test function returns before the promise settles, so the assertion's result is ignored. Make the test `async` and `await` every `resolves`/`rejects`, `findBy` and user-event call. The `eslint-plugin-testing-library` and `vitest` lint rules catch most of these.

</Concept>

<Concept name="Mistake 3: testing implementation details" id="implementation" warn>

Checking state, internal functions, hook calls or CSS classes makes tests break on refactors that change nothing for users. Assert on what's **on screen** and what the component **reports** through its props (`onAdd` was called with the product).

</Concept>

<Concept name="Mistake 4: getByTestId everywhere" id="testid" warn>

`data-testid` hooks tests to markup the user never sees, and skips the free accessibility check of `getByRole`. Use it only when nothing else identifies the element (a canvas, a complex chart). If you can't find a button by role and name, fix the button.

</Concept>

<Concept name="Mistake 5: snapshot overuse" id="snapshots" warn>

`expect(container).toMatchSnapshot()` saves the whole rendered HTML and fails on any change. Large snapshots get updated with `-u` without being read, so they protect nothing. Keep snapshots small and intentional (an error message, a formatted string), and prefer explicit assertions.

</Concept>

<Concept name="Mistake 6: silencing act warnings" id="act" warn>

"An update to X inside a test was not wrapped in act(…)" means something changed after your test stopped looking. Don't wrap random lines in `act` to hide it: **wait for the result** with `findBy` or `waitFor`, so the test actually checks the final state.

</Concept>

These tests all pass… on the real code **and** on every broken version. Fix them so they catch the bugs. `applyCoupon(total, code)` takes 10% off for `SAVE10` (any case) and leaves the total alone for unknown codes; `checkCoupon(code)` resolves to whether a code is valid.

```js code file=coupons.js
function applyCoupon(total, code) {
  return code.toUpperCase() === "SAVE10" ? total * 0.9 : total;
}

async function checkCoupon(code) {
  return code.toUpperCase() === "SAVE10";
}
```

```js starter
test("applies a coupon", () => {
  expect(applyCoupon(100, "SAVE10")).toBeTruthy();
});

test("unknown codes work", () => {
  expect(applyCoupon(100, "NOPE")).toBeDefined();
});

test("checks a coupon", () => {
  expect(checkCoupon("SAVE10")).resolves.toBe(true);
});
```

```js bug title="Discount is 20%, not 10%" hint="Assert the exact discounted total."
function applyCoupon(total, code) {
  return code.toUpperCase() === "SAVE10" ? total * 0.8 : total;
}

async function checkCoupon(code) {
  return code.toUpperCase() === "SAVE10";
}
```

```js bug title="Unknown codes give a discount too" hint="An unknown code should leave the total unchanged: check the exact value."
function applyCoupon(total, code) {
  return total * 0.9;
}

async function checkCoupon(code) {
  return code.toUpperCase() === "SAVE10";
}
```

```js bug title="checkCoupon always says no" hint="Await the async check (make the test async)."
function applyCoupon(total, code) {
  return code.toUpperCase() === "SAVE10" ? total * 0.9 : total;
}

async function checkCoupon(code) {
  return false;
}
```

```js bug title="Case-sensitive codes" hint="Try the code typed in lowercase."
function applyCoupon(total, code) {
  return code === "SAVE10" ? total * 0.9 : total;
}

async function checkCoupon(code) {
  return code.toUpperCase() === "SAVE10";
}
```

```js solution
test("SAVE10 takes 10% off, in any case", () => {
  expect(applyCoupon(100, "SAVE10")).toBe(90);
  expect(applyCoupon(100, "save10")).toBe(90);
});

test("unknown codes leave the total alone", () => {
  expect(applyCoupon(100, "NOPE")).toBe(100);
});

test("checkCoupon accepts SAVE10 and rejects others", async () => {
  await expect(checkCoupon("SAVE10")).resolves.toBe(true);
  await expect(checkCoupon("NOPE")).resolves.toBe(false);
});
```
