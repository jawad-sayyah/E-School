**React Testing Library** (RTL) renders components into a simulated browser page (jsdom) and gives you queries to find elements **the way a user would**: by their role and accessible name, their label, their text. The guiding idea: *the more your tests resemble the way your software is used, the more confidence they give you.*

<Concept name="render and screen" id="render">

```jsx file=ProductCard.test.jsx
import { render, screen } from "@testing-library/react";
import { expect, test } from "vitest";
import ProductCard from "./ProductCard";

test("shows the product name and price", () => {
  render(<ProductCard product={{ id: 1, name: "Tea", price: 2 }} />);

  expect(screen.getByRole("heading", { name: "Tea" })).toBeInTheDocument();
  expect(screen.getByText("$2.00")).toBeInTheDocument();
});
```

- **`render(<Component />)`** mounts the component into a fresh DOM. (RTL cleans up after each test.)
- **`screen`** queries the whole rendered page.
- **`toBeInTheDocument()`** and friends come from `@testing-library/jest-dom`, which adds DOM matchers like `toHaveTextContent`, `toBeDisabled`, `toHaveValue`, `toBeChecked`, `toHaveAttribute`.

</Concept>

<Concept name="Query priority" id="priority">

Pick the query a user (or a screen reader) would use. In order of preference:

| Query | Finds | Example |
| --- | --- | --- |
| `getByRole` | elements by role and accessible name | `getByRole("button", { name: "Add to cart" })` |
| `getByLabelText` | form fields by their label | `getByLabelText("Quantity")` |
| `getByPlaceholderText` | fields by placeholder (when there's no label) | `getByPlaceholderText("Search")` |
| `getByText` | non-interactive text | `getByText("Your cart is empty")` |
| `getByDisplayValue` | inputs by their current value | `getByDisplayValue("3")` |
| `getByAltText` / `getByTitle` | images, titled elements | `getByAltText("A cup of coffee")` |
| `getByTestId` | `data-testid` | the last resort, when nothing else works |

`getByRole` is first because it also checks **accessibility**: if a test can't find your button by role and name, neither can a screen reader user.

</Concept>

<Concept name="get, query and find" id="variants">

| Prefix | When nothing matches | Use it for |
| --- | --- | --- |
| `getBy…` | throws | elements that should be there |
| `queryBy…` | returns `null` | asserting something is **not** there: `expect(screen.queryByText("Sold out")).not.toBeInTheDocument()` |
| `findBy…` | a promise that rejects after a timeout | elements that appear **later** (after a fetch): `await screen.findByText("Tea")` |

Each has an `…AllBy…` version returning an array (`getAllByRole("listitem")`).

</Concept>

<HowItWorks title="Test behavior, not implementation">

A test that reads a component's state, calls its internal functions or checks CSS class names breaks whenever you refactor, even when the user sees no difference. RTL deliberately doesn't give you access to state or instances. You render, you look at the DOM like a user, you interact like a user, and you assert on what changed on screen. Then you can rewrite the component (a reducer instead of `useState`, a different library) and the tests still pass, as long as it behaves the same.

</HowItWorks>

```jsx solution file=/ProductCard.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import { expect, test, vi } from "vitest";
import ProductCard from "./ProductCard";

const tea = { id: 1, name: "Tea", price: 2.5, onSale: false };

test("shows the name and the price with two decimals", () => {
  render(<ProductCard product={tea} onAdd={vi.fn()} />);
  expect(screen.getByRole("heading", { name: "Tea" })).toBeInTheDocument();
  expect(screen.getByText("$2.50")).toBeInTheDocument();
});

test("shows the Sale badge only for products on sale", () => {
  const { unmount } = render(<ProductCard product={tea} onAdd={vi.fn()} />);
  expect(screen.queryByText("Sale")).not.toBeInTheDocument();
  unmount();
  render(<ProductCard product={{ ...tea, onSale: true }} onAdd={vi.fn()} />);
  expect(screen.getByText("Sale")).toBeInTheDocument();
});

test("Add to cart calls onAdd with the product", () => {
  const onAdd = vi.fn();
  render(<ProductCard product={tea} onAdd={onAdd} />);
  fireEvent.click(screen.getByRole("button", { name: "Add to cart" }));
  expect(onAdd).toHaveBeenCalledWith(tea);
});
```
