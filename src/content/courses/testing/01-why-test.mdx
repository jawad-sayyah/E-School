You change the discount code logic. Does the cart total still work? The badge? Checkout? Clicking through every flow after every change takes ten minutes, so nobody does it, and bugs slip out. An **automated test** is code that checks your code: it runs in seconds, every time, on every change.

<Concept name="What a test looks like" id="anatomy">

<Playground file="cart.test.js" expected={["✓ adds price × qty for every line", "✓ an empty cart is 0"]}>

```js
function getTotal(cart) {
  return cart.reduce((sum, line) => sum + line.price * line.qty, 0);
}

// A tiny test: run the code, compare the result with what you expect
function test(name, fn) {
  try {
    fn();
    console.log("✓ " + name);
  } catch (e) {
    console.log("✗ " + name + ": " + e.message);
  }
}
function expectToBe(actual, expected) {
  if (actual !== expected) throw new Error(`expected ${expected}, got ${actual}`);
}

test("adds price × qty for every line", () => {
  expectToBe(getTotal([{ price: 4, qty: 2 }, { price: 3, qty: 1 }]), 11);
});
test("an empty cart is 0", () => {
  expectToBe(getTotal([]), 0);
});
```

</Playground>

That's all a test is: **arrange** some input, **act** by calling the code, **assert** the result. Test runners like **Vitest** give you `test`, `expect` and dozens of matchers ready-made, run every test file, and report what failed and why. Change `price * qty` to `price + qty` in the playground and run it: the first test fails.

</Concept>

<Concept name="The testing pyramid" id="pyramid">

| Level | Tests… | Speed | How many |
| --- | --- | --- | --- |
| **Unit** | one function or component on its own (`getTotal`, `cartReducer`, `<Price />`) | milliseconds | lots |
| **Integration** | several pieces together (the cart page with its reducer and context) | fast | some |
| **End-to-end (E2E)** | the real app in a real browser, like a user (add to cart → checkout) | seconds | a few |

Lower levels are fast and pinpoint the broken line; higher levels give confidence that the whole thing works. A healthy project has many unit tests, a good layer of integration tests (for React, that's where Testing Library shines), and a handful of E2E tests for the critical paths.

</Concept>

<HowItWorks title="What tests buy you">

- **Regression safety:** a bug fixed once, with a test, stays fixed.
- **Fearless refactoring:** change how the code works; if the tests still pass, what it does hasn't changed.
- **Documentation:** a test named "removes the line when qty drops to 0" says what the code is supposed to do.
- **Faster reviews and deploys:** CI runs the suite on every pull request, so reviewers and the deploy pipeline trust the change.

Tests aren't free: they're code to write and maintain. That's why this course is about writing **good** tests: ones that catch real bugs and don't break when you refactor.

</HowItWorks>

<TestExercise
  id="first-tests"
  title="Your first tests: isFreeShipping"
  hints={[
    "Test both sides of the line: a total just under 50 and exactly 50.",
    "One bug uses `>` instead of `>=`; another ignores the quantity; another treats an empty cart as free.",
  ]}
>

`isFreeShipping(cart)` returns `true` when the cart total is **$50 or more**. Write tests that pass on this code and catch the hidden buggy versions. The starter has one test; it isn't enough.

```js code file=shipping.js
function isFreeShipping(cart) {
  const total = cart.reduce((sum, line) => sum + line.price * line.qty, 0);
  return total >= 50;
}
```

```js starter
test("a big order ships free", () => {
  expect(isFreeShipping([{ price: 60, qty: 1 }])).toBe(true);
});
```

```js bug title="Uses > instead of >=" hint="What should happen at exactly $50?"
function isFreeShipping(cart) {
  const total = cart.reduce((sum, line) => sum + line.price * line.qty, 0);
  return total > 50;
}
```

```js bug title="Ignores the quantity" hint="Try a cheap item bought many times, like 10 × $5."
function isFreeShipping(cart) {
  const total = cart.reduce((sum, line) => sum + line.price, 0);
  return total >= 50;
}
```

```js bug title="Always free" hint="Do you have a test where shipping is NOT free?"
function isFreeShipping(cart) {
  return true;
}
```

```js solution
test("$50 or more ships free", () => {
  expect(isFreeShipping([{ price: 60, qty: 1 }])).toBe(true);
  expect(isFreeShipping([{ price: 50, qty: 1 }])).toBe(true);
});

test("quantity counts towards the total", () => {
  expect(isFreeShipping([{ price: 5, qty: 10 }])).toBe(true);
});

test("under $50 doesn't", () => {
  expect(isFreeShipping([{ price: 49, qty: 1 }])).toBe(false);
  expect(isFreeShipping([])).toBe(false);
});
```
