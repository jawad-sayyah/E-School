Accessibility bugs (a button without a name, an input without a label, an image without alt text) are easy to ship and hard to notice if you use a mouse and can see the screen. Two kinds of tests catch them automatically.

<Concept name="jest-axe: an automatic audit" id="jest-axe">

**axe-core** is the engine behind most accessibility checkers. **jest-axe** runs it on a rendered component and adds the `toHaveNoViolations` matcher:

```jsx file=ProductCard.test.jsx
import { render } from "@testing-library/react";
import { axe } from "jest-axe";
import { expect, test } from "vitest";
import "jest-axe/extend-expect";

test("the product card has no accessibility violations", async () => {
  const { container } = render(<ProductCard product={tea} onAdd={() => {}} />);
  expect(await axe(container)).toHaveNoViolations();
});
```

```text file=terminal
 ✗ the product card has no accessibility violations

   Expected the HTML found at $('button') to have no violations:
   <button><svg …></svg></button>

   Received:
   "Buttons must have discernible text (button-name)"
   Fix any of the following:
     Element does not have inner text that is visible to screen readers
     aria-label attribute does not exist or is empty
```

One line per component catches missing names, labels and alt text, invalid ARIA, duplicate ids, and more. It **can't** judge everything (whether alt text is meaningful, whether focus order makes sense, whether the page works with a keyboard): automated checks find roughly a third of real issues, so keep testing by hand too.

</Concept>

<Concept name="Your queries already test accessibility" id="queries">

Every `getByRole("button", { name: "Add to cart" })` is a small accessibility test: it fails if the element isn't a real button or has no accessible name. `getByLabelText("Email")` fails if the input isn't labelled. Writing tests the way Testing Library recommends means accessibility regressions break the build, for free.

</Concept>

<HowItWorks title="Where axe fits">

Run axe in component tests for each meaningful component state (empty cart, error message shown, dialog open), and in end-to-end tests on whole pages (`@axe-core/playwright`). Add the `eslint-plugin-jsx-a11y` lint rules to catch issues while typing. Together they form layers: lint while coding, axe and role queries in tests, and a manual keyboard and screen-reader pass for the flows that matter most.

</HowItWorks>

`FavoriteCard` should have: an image described as **A cup of coffee**, a quantity input labelled **Quantity**, and an icon-only button named **Save to favorites**. Write tests with role and label queries that fail on each inaccessible version.

```jsx code file=/FavoriteCard.js
export default function FavoriteCard() {
  return (
    <article>
      <img src="/coffee.jpg" alt="A cup of coffee" />
      <label>
        Quantity <input type="number" defaultValue={1} />
      </label>
      <button aria-label="Save to favorites">♡</button>
    </article>
  );
}
```

```jsx starter file=/FavoriteCard.test.js
import { render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import { expect, test } from "vitest";
import FavoriteCard from "./FavoriteCard";

test("renders", () => {
  render(<FavoriteCard />);
  expect(screen.getByRole("article")).toBeInTheDocument();
});
```

```jsx bug file=/FavoriteCard.js title="Input with only a placeholder" hint="Query the input by its label."
export default function FavoriteCard() {
  return (
    <article>
      <img src="/coffee.jpg" alt="A cup of coffee" />
      Quantity <input type="number" placeholder="Quantity" defaultValue={1} />
      <button aria-label="Save to favorites">♡</button>
    </article>
  );
}
```

```jsx solution file=/FavoriteCard.test.js
import { render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import { expect, test } from "vitest";
import FavoriteCard from "./FavoriteCard";

test("every control and image has an accessible name", () => {
  render(<FavoriteCard />);
  expect(screen.getByRole("img", { name: "A cup of coffee" })).toBeInTheDocument();
  expect(screen.getByLabelText("Quantity")).toHaveValue(1);
  expect(screen.getByRole("button", { name: "Save to favorites" })).toBeInTheDocument();
});
```
