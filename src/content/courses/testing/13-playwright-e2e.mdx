Unit and integration tests run in jsdom, a simulated page. **End-to-end (E2E)** tests drive a **real browser** against the **real app** (built and served), clicking and typing like a user. They're the slowest tests, so keep them for the few flows that must never break: sign-in, add to cart, checkout.

<Concept name="A checkout test" id="checkout">

E2E tests can't run inside this page (they need a real browser controlling your app), so here's the code and what a run prints. You'll run tests like this yourself in the MiniShop project.

```ts file=e2e/checkout.spec.ts
import { expect, test } from "@playwright/test";

test("a customer can buy a coffee", async ({ page }) => {
  await page.goto("/");
  await page.getByRole("link", { name: "Products" }).click();

  await page.getByRole("button", { name: "Add Coffee" }).click();
  await expect(page.getByLabel("Items in cart")).toHaveText("1");

  await page.getByRole("link", { name: "Cart" }).click();
  await page.getByRole("button", { name: "Checkout" }).click();

  await page.getByLabel("Name").fill("Ada Lovelace");
  await page.getByLabel("Email").fill("ada@example.com");
  await page.getByRole("button", { name: "Place order" }).click();

  await expect(page.getByRole("heading", { name: "Thank you!" })).toBeVisible();
  await expect(page).toHaveURL(/\/orders\/\d+/);
});
```

Playwright's locators mirror Testing Library's: `getByRole`, `getByLabel`, `getByText`. Its `expect` **auto-waits**: `toHaveText` retries until the text appears or a timeout passes, so there are no manual sleeps.

</Concept>

<Concept name="Running and debugging" id="running">

```bash file=terminal
npm init playwright@latest        # adds @playwright/test, a config and example tests
npx playwright test               # run headless, all browsers in the config
npx playwright test --ui          # interactive mode: watch, step through, pick locators
npx playwright test --debug       # step through one test in a visible browser
npx playwright show-report        # the HTML report of the last run
```

Configure `webServer` in `playwright.config.ts` to build and start the app before the tests (this site does exactly that), and turn on `trace: "retain-on-failure"`: when a test fails in CI, the **trace viewer** shows every action, screenshot, network request and console message.

</Concept>

<HowItWorks title="Keeping E2E tests reliable">

E2E tests have a reputation for being **flaky** (failing randomly). Most flakiness has a few causes:

- **Waiting with timers** (`waitForTimeout(2000)`): use auto-waiting assertions instead.
- **Brittle selectors** (`.btn-primary:nth-child(3)`): use role, label and text locators.
- **Shared state** between tests (one test's order leaks into another's cart): give each test its own data, or reset it.
- **Real third-party services** (payments, email): stub them, or use their test modes.

Keep the suite small and focused on critical paths; push everything else down to faster integration and unit tests.

</HowItWorks>
