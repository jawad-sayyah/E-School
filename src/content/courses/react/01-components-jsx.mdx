A React app is a tree of **components**: functions that return a description of some UI. You write that description in **JSX**, which looks like HTML but lives inside JavaScript.

<Concept name="A component is a function" id="component-function">

This file has three components. `App` uses the other two like HTML tags, and `ProductCard` is used three times. Change the text in `Header` and watch the preview.

<ReactPlayground height={380}>

```jsx file=/App.js
function Header() {
  return (
    <header className="header">
      <h1>MiniShop</h1>
    </header>
  );
}

function ProductCard() {
  return (
    <article className="card">
      <h2>Coffee</h2>
      <p>$4</p>
    </article>
  );
}

export default function App() {
  return (
    <main>
      <Header />
      <div className="grid">
        <ProductCard />
        <ProductCard />
        <ProductCard />
      </div>
    </main>
  );
}
```

```css file=/styles.css
body { font-family: system-ui, sans-serif; margin: 0; padding: 16px; }
.header h1 { margin: 0 0 12px; }
.grid { display: flex; gap: 12px; flex-wrap: wrap; }
.card { border: 1px solid #ddd; border-radius: 12px; padding: 12px 16px; }
.card h2 { margin: 0; font-size: 18px; }
.card p { margin: 4px 0 0; color: #555; }
```

</ReactPlayground>

- A component's name **starts with a capital letter**: `ProductCard`, not `productCard`.
- It **returns JSX** (or `null` to show nothing).
- You use it like a tag: `<ProductCard />`. Each use is a separate **instance**.
- `export default` makes `App` the component the page shows.

All three cards say "Coffee" for now. In the next lesson, **props** let each card show a different product.

</Concept>

<Concept name="JSX's rules" id="jsx-rules">

JSX is strict in a few ways HTML isn't:

1. **One parent.** A component returns one element. Wrap siblings in a `<div>`, or in a **fragment** `<>...</>` when you don't want an extra element.
2. **Close every tag.** `<img />`, `<br />`, `<input />`.
3. **camelCase attributes.** `className` instead of `class`, `htmlFor` instead of `for`, `onClick` instead of `onclick`, `tabIndex` instead of `tabindex`.
4. **Curly braces for JavaScript.** Anything inside `{ }` is a JavaScript expression: a variable, a calculation, a function call.

<ReactPlayground height={320}>

```jsx file=/App.js
const product = { name: "Iced Coffee", price: 4.5, qty: 2 };

export default function App() {
  const total = product.price * product.qty;
  return (
    <>
      <h2>{product.name.toUpperCase()}</h2>
      <p>
        {product.qty} × ${product.price.toFixed(2)} = <strong>${total.toFixed(2)}</strong>
      </p>
      <label htmlFor="note">Note for the barista</label>
      <input id="note" placeholder="Extra hot?" />
      {/* A comment in JSX goes inside braces */}
      <p style={{ color: "teal", fontWeight: 600 }}>Free refills today</p>
    </>
  );
}
```

</ReactPlayground>

<Callout type="warn">
Braces hold **expressions** (things that produce a value), not statements. `{if (x) ...}` and `{for (...)}` don't work inside JSX; use a ternary, `&&` or `.map()` instead. You'll see all three soon.
</Callout>

The `style` attribute takes an **object**, so it has two pairs of braces: the outer ones mean "JavaScript here", the inner ones are the object. CSS property names are camelCase there too: `fontWeight`, `backgroundColor`.

</Concept>

<HowItWorks title="Why one parent, and why capital letters?">

JSX is turned into function calls before the code runs. `<h2>Hi</h2>` becomes `jsx("h2", { children: "Hi" })`, which returns a plain object describing the element.

- **One parent:** a function can only return one value. Two sibling tags would be two values, so you wrap them in one parent. A fragment `<>...</>` is a parent that adds nothing to the page.
- **Capital letters:** the compiler looks at the first letter. `<header>` becomes `jsx("header")`, a string, so React makes a real HTML element. `<Header>` becomes `jsx(Header)`, a reference to your function, so React calls it. A lowercase `<productCard />` would look for an HTML tag called `productcard`, which doesn't exist.

</HowItWorks>

<GoDeeper title="Where should components live?">

Small apps can keep several components in one file, as above. As an app grows, the usual convention is **one component per file**, named after it: `ProductCard.jsx` exports `ProductCard`. Then `App.jsx` imports what it needs:

```jsx file=App.jsx
import Header from "./Header";
import ProductCard from "./ProductCard";
```

Never define a component *inside* another component's function. It would be a brand-new function on every render, so React would throw away its elements (and any state inside them) every time the parent renders.

</GoDeeper>

```jsx tests file=/Header.test.js
import { render, screen, within } from "@testing-library/react";
import "@testing-library/jest-dom";
import Header from "./Header";

test("has the MiniShop heading", () => {
  render(<Header />);
  expect(screen.getByRole("heading", { name: "MiniShop" })).toBeInTheDocument();
});

test("is a header landmark", () => {
  render(<Header />);
  expect(screen.getByRole("banner")).toBeInTheDocument();
});

test("has a navigation with Home, Products and Cart links", () => {
  render(<Header />);
  const nav = screen.getByRole("navigation");
  const links = within(nav).getAllByRole("link");
  expect(links.map((a) => a.textContent)).toEqual(["Home", "Products", "Cart"]);
});
```

```jsx solution file=/Header.js
export default function Header() {
  return (
    <header>
      <h1>MiniShop</h1>
      <nav>
        <a href="/">Home</a>
        <a href="/products">Products</a>
        <a href="/cart">Cart</a>
      </nav>
    </header>
  );
}
```
