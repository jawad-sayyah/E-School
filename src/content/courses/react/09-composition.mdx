React doesn't have inheritance for components. Instead, you **compose**: put components inside other components, and pass pieces of UI around like any other value.

<Concept name="Wrappers with children" id="wrappers">

A wrapper component draws the frame and lets the caller decide what goes inside. You met `children` in the Props lesson; it's the main tool for composition.

<ReactPlayground height={360}>

```jsx file=/App.js
function Card({ children, highlight = false }) {
  return <div className={highlight ? "card highlight" : "card"}>{children}</div>;
}

function Dialog({ title, children, actions }) {
  return (
    <div className="dialog" role="dialog" aria-label={title}>
      <h2>{title}</h2>
      <div>{children}</div>
      <footer>{actions}</footer>
    </div>
  );
}

export default function App() {
  return (
    <>
      <Card>
        <h3>Coffee</h3>
        <p>$4.00</p>
      </Card>
      <Card highlight>
        <h3>Today only: Iced Latte</h3>
      </Card>
      <Dialog
        title="Remove item?"
        actions={
          <>
            <button>Cancel</button>
            <button className="danger">Remove</button>
          </>
        }
      >
        <p>Coffee will be removed from your cart.</p>
      </Dialog>
    </>
  );
}
```

`Dialog` has **two slots**: `children` for the body and an `actions` prop for the buttons. Any prop can hold JSX, so a component can have as many slots as it needs (`header`, `sidebar`, `footer`, `icon`…).

</Concept>

<Concept name="Specialization" id="specialization">

Instead of extending a component, make a **specialized version** that renders the general one with some props filled in:

```jsx file=Buttons.jsx
function Button({ variant = "plain", ...rest }) {
  return <button className={`btn btn-${variant}`} {...rest} />;
}

function DangerButton(props) {
  return <Button variant="danger" {...props} />;
}

<DangerButton onClick={removeAll}>Empty cart</DangerButton>
```

`{...rest}` collects every other prop (`onClick`, `children`, `disabled`…) and spreads them onto the inner element, so the specialized version supports everything the general one does.

</Concept>

<Concept name="Composition fixes prop drilling" id="prop-drilling">

**Prop drilling** is passing a prop through components that don't use it, just to reach one deep inside:

<Compare
  wrong="Layout and Sidebar only pass `user` along; they never use it"
  right="App builds the UserMenu itself and hands it over as a slot"
  wrongFile="drilling.jsx"
  rightFile="composed.jsx"
>

```jsx
function App() {
  return <Layout user={user} />;
}
function Layout({ user }) {
  return <Sidebar user={user} />;
}
function Sidebar({ user }) {
  return <UserMenu user={user} />;
}
```

```jsx
function App() {
  return (
    <Layout sidebar={<UserMenu user={user} />} />
  );
}
function Layout({ sidebar }) {
  return <aside>{sidebar}</aside>;
}
```

</Compare>

When the parent creates the element itself and passes it down as a slot, the layers in between don't need to know about `user` at all. For data that many distant components need (the current user, the theme, the cart), **Context** is the other tool; it's in the Hooks course.

</Concept>

<HowItWorks title="Why passing JSX around is cheap">

`<UserMenu user={user} />` is just an object, `{ type: UserMenu, props: { user } }`. Creating it doesn't run `UserMenu`; React only calls the component when that object ends up in the tree it renders. So passing elements through props or `children` is as cheap as passing any other object, and the component that *receives* them decides where they appear.

</HowItWorks>

Write `Panel` in `Panel.js`: a `<section>` with a heading from the `title` prop, the `children` under it, and an optional `footer` slot that's only rendered (inside a `<footer>`) when it's given. `App` already uses it twice.

```jsx starter file=/Panel.js
export default function Panel(props) {
  return <section className="panel">Panel goes here</section>;
}
```

```jsx starter file=/App.js
import Panel from "./Panel";

export default function App() {
  return (
    <>
      <Panel title="Cart" footer={<button>Checkout</button>}>
        <p>Coffee × 2</p>
      </Panel>
      <Panel title="Recently viewed">
        <p>Bagel</p>
      </Panel>
    </>
  );
}
```

```jsx tests file=/Panel.test.js
import { render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import Panel from "./Panel";

test("shows the title as a heading", () => {
  render(<Panel title="Cart"><p>Coffee</p></Panel>);
  expect(screen.getByRole("heading", { name: "Cart" })).toBeInTheDocument();
});

test("renders its children", () => {
  render(<Panel title="Cart"><p>Coffee × 2</p></Panel>);
  expect(screen.getByText("Coffee × 2")).toBeInTheDocument();
});

test("renders the footer slot in a footer", () => {
  render(<Panel title="Cart" footer={<button>Checkout</button>}><p>Coffee</p></Panel>);
  expect(screen.getByRole("button", { name: "Checkout" }).closest("footer")).not.toBeNull();
});

test("leaves out the footer when there isn't one", () => {
  const { container } = render(<Panel title="Cart"><p>Coffee</p></Panel>);
  expect(container.querySelector("footer")).toBeNull();
});
```

```jsx solution file=/Panel.js
export default function Panel({ title, children, footer }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {children}
      {footer && <footer>{footer}</footer>}
    </section>
  );
}
```
