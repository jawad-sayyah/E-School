Props come from the parent. **State** is a component's own memory: data that changes while the user uses the page, like a quantity, a cart or what's typed in a box. When state changes, React renders the component again.

<Concept name="Why a plain variable doesn't work" id="plain-variable">

Click **+** in this preview. Then open the console: the variable *does* change, but the screen doesn't.

<ReactPlayground height={300} console>

```jsx file=/App.js
export default function App() {
  let qty = 1;

  function increase() {
    qty = qty + 1;
    console.log("qty is now", qty);
  }

  return (
    <p>
      Quantity: {qty} <button onClick={increase}>+</button>
    </p>
  );
}
```

</ReactPlayground>

Two problems:

1. **Changing a local variable doesn't tell React to render again**, so the screen keeps the old value.
2. **Even if it did render, `let qty = 1` would run again** and reset it, because rendering means calling the function from the top.

</Concept>

<Concept name="useState" id="use-state">

`useState` solves both: React keeps the value between renders, and the setter function asks for a new render.

<ReactPlayground height={320}>

```jsx file=/App.js
import { useState } from "react";

function QuantityPicker({ name }) {
  const [qty, setQty] = useState(1);

  return (
    <p>
      {name}: <button onClick={() => setQty(qty - 1)}>−</button>{" "}
      <strong>{qty}</strong>{" "}
      <button onClick={() => setQty(qty + 1)}>+</button>
    </p>
  );
}

export default function App() {
  return (
    <>
      <QuantityPicker name="Coffee" />
      <QuantityPicker name="Tea" />
    </>
  );
}
```

</ReactPlayground>

- `useState(1)` returns a pair: the **current value** and a **setter**. The `1` is only used on the first render.
- Calling `setQty(5)` stores 5 and re-renders the component, and this time `useState` returns 5.
- Each instance has **its own** state: the Coffee and Tea pickers don't share a quantity.
- Hooks like `useState` must be called at the **top level** of the component, never inside an `if`, a loop or a nested function.

</Concept>

<Concept name="Never mutate state" id="never-mutate">

For arrays and objects, **don't change the existing value; give the setter a new one**. React compares the old and new value with `Object.is`: if it's the same array (even with new contents), React assumes nothing changed.

<Compare
  wrong="Changes the array React already has, then hands back the same array"
  right="Builds a new array, so React sees a change"
  wrongFile="mutate.jsx"
  rightFile="copy.jsx"
>

```jsx
cart.push(item);
setCart(cart);

user.name = "Ada";
setUser(user);
```

```jsx
setCart([...cart, item]);

setUser({ ...user, name: "Ada" });
```

</Compare>

The everyday recipes:

| To… | Arrays | Objects |
| --- | --- | --- |
| add | `[...arr, item]` | `{ ...obj, key: value }` |
| remove | `arr.filter((x) => x.id !== id)` | `const { key, ...rest } = obj` |
| change one | `arr.map((x) => x.id === id ? { ...x, qty: 2 } : x)` | `{ ...obj, key: newValue }` |

</Concept>

<HowItWorks title="Where state lives">

React stores state **next to the component's position in the tree**, not inside the function. On each render, the `useState` calls are matched up by their **order**: the first `useState` in the component gets the first stored value, the second gets the second, and so on. That's why hooks can't be inside conditions or loops: a skipped call would shift every value after it.

When you call a setter, React doesn't change `qty` right away; the current render's `qty` is a constant. It schedules a new render, and in that render `useState` hands back the new value. The Hooks course shows this "state is a snapshot" idea with a timeline.

</HowItWorks>

<GoDeeper title="Updater functions: setQty(q => q + 1)">

`setQty(qty + 1)` uses the `qty` from the current render. If you call it twice in the same click, both calls see the same old `qty`:

```jsx file=Picker.jsx
function addTwo() {
  setQty(qty + 1);   // qty is 1 → asks for 2
  setQty(qty + 1);   // qty is still 1 → asks for 2 again
}
```

Pass a function instead, and React gives it the latest value in the queue:

```jsx file=Picker.jsx
function addTwo() {
  setQty((q) => q + 1);   // 1 → 2
  setQty((q) => q + 1);   // 2 → 3
}
```

Use the updater form whenever the new state depends on the old one and you might update more than once before the next render.

</GoDeeper>

Make the stepper work: it starts at **1**, the **+** button adds one, and the **−** button takes one away but never goes below 1. Keep the `aria-label`s: the tests use them to find the buttons and the number.

```jsx starter file=/App.js
export default function App() {
  const qty = 1;

  return (
    <div className="stepper">
      <button aria-label="Decrease quantity">−</button>
      <span aria-label="Quantity">{qty}</span>
      <button aria-label="Increase quantity">+</button>
    </div>
  );
}
```

```jsx tests file=/App.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

const qty = () => screen.getByLabelText("Quantity");

test("starts at 1", () => {
  render(<App />);
  expect(qty()).toHaveTextContent("1");
});

test("+ adds one each time", () => {
  render(<App />);
  fireEvent.click(screen.getByLabelText("Increase quantity"));
  fireEvent.click(screen.getByLabelText("Increase quantity"));
  expect(qty()).toHaveTextContent("3");
});

test("− takes one away", () => {
  render(<App />);
  fireEvent.click(screen.getByLabelText("Increase quantity"));
  fireEvent.click(screen.getByLabelText("Decrease quantity"));
  expect(qty()).toHaveTextContent("1");
});

test("never goes below 1", () => {
  render(<App />);
  fireEvent.click(screen.getByLabelText("Decrease quantity"));
  fireEvent.click(screen.getByLabelText("Decrease quantity"));
  expect(qty()).toHaveTextContent("1");
});
```

```jsx solution file=/App.js
import { useState } from "react";

export default function App() {
  const [qty, setQty] = useState(1);

  return (
    <div className="stepper">
      <button
        aria-label="Decrease quantity"
        onClick={() => setQty(qty > 1 ? qty - 1 : 1)}
      >
        −
      </button>
      <span aria-label="Quantity">{qty}</span>
      <button aria-label="Increase quantity" onClick={() => setQty(qty + 1)}>
        +
      </button>
    </div>
  );
}
```
