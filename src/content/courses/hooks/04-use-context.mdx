Some data is needed all over the app: the cart, the logged-in user, the theme, the language. Passing it as props through every layer is **prop drilling**. **Context** lets a parent make a value available to **every** component below it, however deep.

<Concept name="Create, provide, use" id="create-provide-use">

<ReactPlayground height={360}>

```jsx file=/App.js
import { createContext, useContext, useState } from "react";

// 1. Create a context, with a default for components outside any provider
const ThemeContext = createContext("light");

function Button({ children }) {
  // 3. Read it anywhere below the provider
  const theme = useContext(ThemeContext);
  return <button className={`btn ${theme}`}>{children}</button>;
}

function Toolbar() {
  // Toolbar doesn't know or care about the theme
  return (
    <div className="toolbar">
      <Button>Add to cart</Button> <Button>Wishlist</Button>
    </div>
  );
}

export default function App() {
  const [theme, setTheme] = useState("light");
  return (
    // 2. Provide a value to everything inside
    <ThemeContext value={theme}>
      <label>
        <input type="checkbox" checked={theme === "dark"} onChange={(e) => setTheme(e.target.checked ? "dark" : "light")} /> Dark buttons
      </label>
      <Toolbar />
    </ThemeContext>
  );
}
```

```css file=/styles.css

.toolbar { margin-top: 12px; }
.btn { border-radius: 8px; padding: 8px 12px; font-weight: 600; border: 1px solid #ccc; }
.btn.light { background: white; color: #222; }
.btn.dark { background: #1a1d2e; color: #61dafb; border-color: #1a1d2e; }
```

</ReactPlayground>

1. **`createContext(defaultValue)`** creates the context. The default is used only by components with no provider above them.
2. **`<ThemeContext value={...}>`** provides a value to its whole subtree. (Before React 19 you wrote `<ThemeContext.Provider value={...}>`; that still works.)
3. **`useContext(ThemeContext)`** reads the value from the **nearest** provider above.

When the provided value changes, every component that reads that context re-renders with the new value.

</Concept>

<Concept name="A CartProvider and a useCart hook" id="cart-provider">

The real-world pattern combines context with state (or a reducer) in one **provider component**, plus a small custom hook so components never touch the context object directly.

```jsx file=CartContext.jsx
import { createContext, useContext, useReducer } from "react";
import { cartReducer } from "./cartReducer";

const CartContext = createContext(null);

export function CartProvider({ children }) {
  const [cart, dispatch] = useReducer(cartReducer, []);
  const count = cart.reduce((n, l) => n + l.qty, 0);
  return <CartContext value={{ cart, count, dispatch }}>{children}</CartContext>;
}

export function useCart() {
  const value = useContext(CartContext);
  if (!value) throw new Error("useCart must be used inside <CartProvider>");
  return value;
}
```

```jsx file=main.jsx
<CartProvider>
  <App />          {/* any component inside can call useCart() */}
</CartProvider>
```

Now `Header` calls `const { count } = useCart()`, `ProductCard` calls `const { dispatch } = useCart()`, and nothing in between passes cart props. The `null` default plus the check in `useCart` gives a clear error if someone forgets the provider.

</Concept>

<HowItWorks title="How React finds the value">

When a component calls `useContext(SomeContext)`, React walks **up** the tree from that component to the nearest `<SomeContext>` provider and returns its `value`. No provider found? It returns the default from `createContext`.

React also remembers which components read which context. When a provider's `value` changes (compared with `Object.is`), React re-renders those readers, **even if they're inside `memo` components** whose props didn't change.

</HowItWorks>

<GoDeeper title="Context and performance">

Two things to know as apps grow:

- **A new object every render re-renders every reader.** `value={{ cart, count, dispatch }}` is a new object each time the provider renders. If the provider re-renders for unrelated reasons, wrap the value in `useMemo(() => ({ cart, count, dispatch }), [cart, count])`.
- **Split contexts by how often they change.** Put `dispatch` (which never changes) in its own context and `cart` in another, so components that only dispatch don't re-render when the cart changes.

Context is for sharing values, not a full state manager. For large, frequently changing app state, libraries like Zustand subscribe components to just the slices they use (React Ecosystem course).

</GoDeeper>

`Header` and `AddButton` are far apart and shouldn't pass props through `Layout`. Finish `CartContext.js`: a `CartProvider` that holds a `count` and an `add` function, and a `useCart()` hook that returns them (and throws a helpful error outside the provider). `App.js` already uses them.

```jsx starter file=/CartContext.js
export function CartProvider({ children }) {
  return children;
}

export function useCart() {
  return { count: 0, add: () => {} };
}
```

```jsx starter file=/App.js
import { CartProvider, useCart } from "./CartContext";

function Header() {
  const { count } = useCart();
  return <header>Cart: <span aria-label="Items in cart">{count}</span></header>;
}

function AddButton() {
  const { add } = useCart();
  return <button onClick={add}>Add coffee</button>;
}

function Layout() {
  return (
    <main>
      <p>Today's special: coffee</p>
      <AddButton />
    </main>
  );
}

export default function App() {
  return (
    <CartProvider>
      <Header />
      <Layout />
    </CartProvider>
  );
}
```

```jsx solution file=/CartContext.js
import { createContext, useContext, useState } from "react";

const CartContext = createContext(null);

export function CartProvider({ children }) {
  const [count, setCount] = useState(0);
  const add = () => setCount((c) => c + 1);
  return <CartContext value={{ count, add }}>{children}</CartContext>;
}

export function useCart() {
  const value = useContext(CartContext);
  if (!value) throw new Error("useCart must be used inside <CartProvider>");
  return value;
}
```
