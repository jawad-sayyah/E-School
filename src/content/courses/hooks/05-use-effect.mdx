Rendering must be pure: no timers, no network, no touching the page outside React. But apps need those things. **Effects** are where they go: code that runs **after** React has updated the screen, to keep something outside React in sync with your component.

<Concept name="The shape of an effect" id="shape">

```jsx file=Effect.jsx
useEffect(() => {
  // setup: start syncing with the outside world
  const connection = connect(roomId);
  return () => {
    // cleanup: stop syncing (optional)
    connection.disconnect();
  };
}, [roomId]); // dependencies: re-sync when these change
```

- The **setup** function runs after the component appears on screen.
- The **cleanup** function (if you return one) runs before the effect runs again, and when the component is removed.
- The **dependency array** lists the values from the component the effect uses. React re-runs the effect only when one of them changed since the last render.

</Concept>

<Concept name="The three dependency forms" id="deps">

| You write | The effect runs |
| --- | --- |
| `useEffect(fn, [a, b])` | after the first render, then whenever `a` or `b` changed |
| `useEffect(fn, [])` | once, after the first render (cleanup on unmount) |
| `useEffect(fn)` | after **every** render |

The array isn't a setting you choose freely: it must list **every** value from the component that the effect reads (props, state, and functions or variables defined in the component). The `react-hooks/exhaustive-deps` lint rule tells you what's missing. If the effect re-runs too often, change the code (move things inside the effect, use an updater function), not the array.

</Concept>

<HowItWorks title="Think in synchronization, not lifecycles">

It's tempting to read `[]` as "on mount" and the cleanup as "on unmount". A better mental model: **an effect describes how to start and stop syncing with something, for the current props and state.** React then makes sure the outside world matches the latest render: when the dependencies change, it stops the old sync (cleanup) and starts a new one (setup).

That's why StrictMode runs setup → cleanup → setup in development: if your effect is a correct "start/stop" pair, doing it twice changes nothing.

</HowItWorks>

<GoDeeper title="Why effects run after paint">

`useEffect` runs after the browser has painted, so slow effect code never makes the screen feel stuck. The cost is that if an effect changes something visible (like measuring an element and moving a tooltip), the user can see a one-frame flicker. For that rare case there's `useLayoutEffect`, which runs after the commit but **before** paint. It's covered two lessons from now.

</GoDeeper>

Keep the browser tab's title in sync with the cart: **MiniShop** when it's empty, and **(2) MiniShop** when it has 2 items.

```jsx starter file=/App.js
import { useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <>
      <p>Items: {count}</p>
      <button onClick={() => setCount(count + 1)}>Add</button>
      <button onClick={() => setCount(0)}>Empty</button>
    </>
  );
}
```

```jsx tests file=/App.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

test("the title is MiniShop when the cart is empty", () => {
  document.title = "";
  render(<App />);
  expect(document.title).toBe("MiniShop");
});

test("the title shows the count", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "Add" }));
  fireEvent.click(screen.getByRole("button", { name: "Add" }));
  expect(document.title).toBe("(2) MiniShop");
});

test("emptying the cart resets the title", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "Add" }));
  fireEvent.click(screen.getByRole("button", { name: "Empty" }));
  expect(document.title).toBe("MiniShop");
});
```

```jsx solution file=/App.js
import { useEffect, useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = count > 0 ? `(${count}) MiniShop` : "MiniShop";
  }, [count]);

  return (
    <>
      <p>Items: {count}</p>
      <button onClick={() => setCount(count + 1)}>Add</button>
      <button onClick={() => setCount(0)}>Empty</button>
    </>
  );
}
```
