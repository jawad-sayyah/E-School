You know the basics of `useState`. This lesson explains the one idea that clears up almost every state puzzle: **each render has its own fixed values. State is a snapshot.**

<Concept name="Setting state doesn't change the variable" id="snapshot">

Click the button and look at the console. It logs the **old** value, even though `setQty` was just called.

<ReactPlayground height={280} console>

```jsx file=/App.js
import { useState } from "react";

export default function App() {
  const [qty, setQty] = useState(1);

  function handleClick() {
    setQty(qty + 1);
    console.log("right after setQty:", qty);
  }

  return <button onClick={handleClick}>Quantity: {qty}</button>;
}
```

</ReactPlayground>

`qty` is a `const` in this render. `setQty` doesn't change it; it asks React for a **new render**, and only in that render will `useState` return the new value. The event handler belongs to the render it was created in, so it sees that render's `qty` forever.

</Concept>

<Concept name="Three updates, one result" id="batching">

What happens when one click calls the setter three times? Step through it.

```jsx
function Picker() {
  const [qty, setQty] = useState(1);

  function addThree() {
    setQty(qty + 1);
    setQty(qty + 1);
    setQty(qty + 1);
  }
  return <button onClick={addThree}>Quantity: {qty}</button>;
}
```

</StateTimeline>

**Batching:** React collects every state update from one event (and in React 18+, from timeouts and promises too) and renders **once** at the end. That's faster, and you never see a half-updated screen.

</Concept>

<Concept name="Updater functions" id="updaters">

When the next value depends on the previous one, pass a **function** to the setter. React puts the function itself in the queue and, while processing it, passes in the result of the update before it.

<StateTimeline
  title="Calling setQty(q => q + 1) three times"
  frames={[
    { line: 5, render: 1, snapshot: { qty: "1" }, queue: [{ update: "q => q + 1" }], screen: "Quantity: 1", note: "The function goes into the queue as it is. It hasn't run yet." },
    { line: 7, render: 1, snapshot: { qty: "1" }, queue: [{ update: "q => q + 1" }, { update: "q => q + 1" }, { update: "q => q + 1" }], screen: "Quantity: 1", note: "Three functions are queued." },
    { line: 2, render: 2, snapshot: { qty: "4" }, queue: [{ update: "q => q + 1", result: "1 + 1 = 2" }, { update: "q => q + 1", result: "2 + 1 = 3" }, { update: "q => q + 1", result: "3 + 1 = 4" }], screen: "Quantity: 4", note: "While rendering, React runs each updater with the result of the previous one: 1 → 2 → 3 → 4. Render 2 sees qty = 4." },
  ]}
>

```jsx
function Picker() {
  const [qty, setQty] = useState(1);

  function addThree() {
    setQty((q) => q + 1);
    setQty((q) => q + 1);
    setQty((q) => q + 1);
  }
  return <button onClick={addThree}>Quantity: {qty}</button>;
}
```

</StateTimeline>

Use an updater whenever the new state is calculated **from the old state** and more than one update might be queued: several calls in a row, a callback from a timer or a subscription, or a `useCallback` with no dependencies. Name the parameter after the state (`q` for `qty`, `prev`, or `c` for `cart`).

</Concept>

<Concept name="Lazy initial state" id="lazy-init">

The argument to `useState` is only used on the first render, but if it's an expensive call it still **runs** on every render:

```jsx file=Cart.jsx
const [cart, setCart] = useState(loadCartFromStorage());       // runs every render
const [cart, setCart] = useState(() => loadCartFromStorage());  // runs once
```

Passing a **function** (not calling it) tells React to call it only for the first render. Use it for reading localStorage, parsing big data or building large initial structures.

</Concept>

<GoDeeper title="Objects in state: replace, don't merge">

Unlike the old `this.setState`, a hook's setter **replaces** the value; it doesn't merge objects:

```jsx file=Form.jsx
const [form, setForm] = useState({ name: "", email: "" });

setForm({ name: "Ada" });               // email is gone!
setForm({ ...form, name: "Ada" });      // keeps email
setForm((f) => ({ ...f, name: "Ada" })); // same, safe with queued updates
```

If two values change independently, it's often simpler to use two `useState` calls. If several values change together according to rules, `useReducer` (next lesson) fits better.

</GoDeeper>

<ReactExercise
  id="add-three"
  title="Make +3 add three"
  hints={[

    "Switch to updater functions: `setQty((q) => q + 1)`.",

The **+3** button should add three, but it only adds one. Fix it while keeping three separate `setQty` calls (the shop's real code does three different steps there).

```jsx starter file=/App.js
import { useState } from "react";

export default function App() {
  const [qty, setQty] = useState(0);

  function addThree() {
    setQty(qty + 1); // step 1: add the item
    setQty(qty + 1); // step 2: add the free sample
    setQty(qty + 1); // step 3: add the gift
  }

  return (
    <>
      <p>Items: {qty}</p>
      <button onClick={addThree}>+3</button>
    </>
  );
}
```

```jsx tests file=/App.test.js
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

test("one click adds three", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "+3" }));
  expect(screen.getByText("Items: 3")).toBeInTheDocument();
});

test("two clicks add six", () => {
  render(<App />);
  fireEvent.click(screen.getByRole("button", { name: "+3" }));
  fireEvent.click(screen.getByRole("button", { name: "+3" }));
  expect(screen.getByText("Items: 6")).toBeInTheDocument();
});
```

```jsx solution file=/App.js
import { useState } from "react";

export default function App() {
  const [qty, setQty] = useState(0);

  function addThree() {
    setQty((q) => q + 1); // step 1: add the item
    setQty((q) => q + 1); // step 2: add the free sample
    setQty((q) => q + 1); // step 3: add the gift
  }

  return (
    <>
      <p>Items: {qty}</p>
      <button onClick={addThree}>+3</button>
    </>
  );
}
```
