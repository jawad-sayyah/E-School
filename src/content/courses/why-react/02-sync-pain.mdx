A real cart needs more than "add": adding Coffee twice should show **Coffee × 2**, not two Coffee lines, and every line needs a **Remove** button. Each new feature means more "find the element and fix it" code, and more chances to forget one place.

<Concept name="One click, three updates" id="three-updates">

Here's the cart with quantities and removing. Try this in the preview:

1. Add Coffee twice and Tea once. The badge says 3.
2. Remove Coffee. The list and the total are right… but look at the badge.

<ReactPlayground template="vanilla" height={460}>

```js file=/index.js
import "./styles.css";

const products = [
  { id: 1, name: "Coffee", price: 4 },
  { id: 2, name: "Bagel", price: 3 },
  { id: 3, name: "Tea", price: 2 },
];
let cart = []; // lines like { id, name, price, qty }

const productList = document.getElementById("products");
const cartList = document.getElementById("cart");
const total = document.getElementById("total");
const badge = document.getElementById("badge");

const getTotal = () => cart.reduce((sum, l) => sum + l.price * l.qty, 0);
const getCount = () => cart.reduce((sum, l) => sum + l.qty, 0);

for (const product of products) {
  const li = document.createElement("li");
  li.textContent = `${product.name} $${product.price} `;
  const button = document.createElement("button");
  button.textContent = "Add";
  button.addEventListener("click", () => add(product));
  li.append(button);
  productList.append(li);
}

function add(product) {
  const line = cart.find((l) => l.id === product.id);
  if (line) {
    line.qty++;
    // find the existing <li> and fix its text
    document.getElementById(`line-${product.id}`).firstChild.textContent =
      `${line.name} × ${line.qty} `;
  } else {
    cart.push({ ...product, qty: 1 });
    // build a new <li> with its own Remove button
    const li = document.createElement("li");
    li.id = `line-${product.id}`;
    li.append(`${product.name} × 1 `);
    const remove = document.createElement("button");
    remove.textContent = "Remove";
    remove.addEventListener("click", () => removeLine(product.id));
    li.append(remove);
    cartList.append(li);
  }
  total.textContent = getTotal();
  badge.textContent = getCount();
}

function removeLine(id) {
  cart = cart.filter((l) => l.id !== id);
  document.getElementById(`line-${id}`).remove();
  total.textContent = getTotal();
}
```

`removeLine` updates the list and the total but **forgets the badge**. Nothing crashes, no error shows up in the console. The page just quietly lies. This is the most common kind of UI bug: the data is right, the screen is out of sync.

</Concept>

<Concept name="The work grows with every feature" id="work-grows">

Count the updates each action needs:

| Action | Cart list | Total | Badge | "Cart is empty" message |
| --- | --- | --- | --- | --- |
| Add a new product | create an item | update | update | hide |
| Add one more of a product | find the item, fix its text | update | update | — |
| Remove a line | find the item, remove it | update | update | show if empty |
| Empty the cart | remove every item | update | update | show |

Every new feature (a discount, a "free shipping" banner, a checkout button that's disabled when the cart is empty) adds a column, and *every* action must remember it. With four features and four actions, that's sixteen places to get right.

</Concept>

<HowItWorks title="Why the bugs happen">

The cart's **state** (the data that changes over time) lives in one place: the `cart` array. But the page shows things **derived** from that state in many places. In imperative code, each action has to know every place that depends on the state. The knowledge is spread out, so it's easy to miss one.

The fix is to flip it around: write *one* function that turns the state into the whole page, and run it after every change. Then no action needs to know what the page looks like. That's exactly the idea React is built on, and the next lesson shows it.

</HowItWorks>
