Here's the cart from the last lesson, quantities and Remove included, rewritten in React. Try the same steps: add Coffee twice and Tea once, then remove Coffee. The badge is right this time, and nowhere in the code is there a line that updates it.

<ReactPlayground height={520}>

```jsx file=/App.js
import { useState } from "react";

const products = [
  { id: 1, name: "Coffee", price: 4 },
  { id: 2, name: "Bagel", price: 3 },
  { id: 3, name: "Tea", price: 2 },
];

export default function App() {
  const [cart, setCart] = useState([]);

  // Everything below is worked out from `cart` on every render
  const total = cart.reduce((sum, l) => sum + l.price * l.qty, 0);
  const count = cart.reduce((sum, l) => sum + l.qty, 0);

  function add(product) {
    const line = cart.find((l) => l.id === product.id);
    if (line) {
      setCart(cart.map((l) => (l.id === product.id ? { ...l, qty: l.qty + 1 } : l)));
    } else {
      setCart([...cart, { ...product, qty: 1 }]);
    }
  }

  function remove(id) {
    setCart(cart.filter((l) => l.id !== id));
  }

  return (
    <main>
      <header>
        MiniShop <span className="badge" aria-label="Items in cart">{count}</span>
      </header>
      <ul>
        {products.map((product) => (
          <li key={product.id}>
            {product.name} ${product.price}{" "}
            <button onClick={() => add(product)}>Add</button>
          </li>
        ))}
      </ul>
      <h2>Cart</h2>
      {cart.length === 0 && <p>Your cart is empty.</p>}
      <ul>
        {cart.map((line) => (
          <li key={line.id}>
            {line.name} × {line.qty}{" "}
            <button onClick={() => remove(line.id)}>Remove</button>
          </li>
        ))}
      </ul>
      <p>Total: ${total}</p>
    </main>
  );
}
```

<Concept name="Describe, don't update" id="describe">

Compare `remove` with the vanilla version:

- **Vanilla:** change the array, find the list item and delete it, update the total, update the badge (or forget to).
- **React:** `setCart(cart.filter(...))`. That's it.

The `return (...)` part describes the *whole* page for any cart: the badge shows `count`, the list shows one item per line, the empty message shows when the cart is empty. When the cart changes, React runs `App` again to get the new description, and updates the screen to match. You never write "now update the badge".

This is the idea behind React in one line: **UI = f(state)**. The page is a function of the state.

</Concept>

<Concept name="The pieces" id="pieces">

- **Component:** a function that returns what to show, here `App`. Its name starts with a capital letter.
- **JSX:** the HTML-like code in the `return`. It's JavaScript underneath, so `{count}` drops a value in, and `{cart.map(...)}` turns an array into list items.
- **State:** `const [cart, setCart] = useState([])` gives you the current cart and a function to replace it. Calling `setCart` tells React "the data changed, draw the page again".

<Callout type="react">
Notice that `add` and `remove` never change `cart` itself: they build a **new** array with `map`, `filter` or spread. React compares the old and the new value to see that something changed, so mutating with `push` or `qty++` would leave the screen stale. The React Fundamentals course covers this in detail.
</Callout>
</Concept>

<GoDeeper title="What JSX turns into">

Browsers don't understand JSX. A build tool (Vite, here) turns each tag into a function call before the code runs:

```jsx
<span className="badge">{count}</span>
```

becomes roughly

```js
jsx("span", { className: "badge", children: count });
```

and that call returns a plain object, `{ type: "span", props: { className: "badge", children: 1 } }`. A component's JSX is a tree of these objects: a cheap description of the page. React compares the new tree with the previous one (this is called **reconciliation**) and only then touches the real DOM. The How React Works course goes through it in depth.

</GoDeeper>
