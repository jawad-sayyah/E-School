Before React, let's build the cart the way you would with the JavaScript you already know: find elements on the page, create new ones, and change their text when something happens. This is called **vanilla JavaScript**: no libraries.

Our page has three things that depend on the cart: the **cart list**, the **total**, and the **badge** in the header that counts the items.

<Concept name="The page and the script" id="page-and-script">

The HTML has empty spots with ids; the script fills them in. Click **Add** and watch all three spots change. Then read `addToCart` to see the work behind it.

```js file=/index.js
import "./styles.css";

const products = [
  { id: 1, name: "Coffee", price: 4 },
  { id: 2, name: "Bagel", price: 3 },
  { id: 3, name: "Tea", price: 2 },
];
let cart = [];

const productList = document.getElementById("products");
const cartList = document.getElementById("cart");
const total = document.getElementById("total");
const badge = document.getElementById("badge");

// Build the product list once
for (const product of products) {
  const li = document.createElement("li");
  li.textContent = `${product.name} $${product.price} `;
  const button = document.createElement("button");
  button.textContent = "Add";
  button.addEventListener("click", () => addToCart(product));
  li.append(button);
  productList.append(li);
}

function addToCart(product) {
  cart.push(product);

  // The data changed. Now update the page by hand, in three places:
  const li = document.createElement("li");   // 1. the cart list
  li.textContent = product.name;
  cartList.append(li);
  total.textContent = cart.reduce((sum, p) => sum + p.price, 0);   // 2. the total
  badge.textContent = cart.length;   // 3. the badge
}
```

<Concept name="Two copies of the truth" id="two-copies">

Look at what the script keeps track of:

- the **data**: the `cart` array;
- the **page**: the list items, the total text and the badge text.

They are two separate copies of the same truth. Every time the data changes, *you* must make the page match it, line by line. Forget one line and the page lies to the user.

<Callout type="warn">
Adding is the easy case. Removing an item, changing a quantity or emptying the cart each need their own "find the right element and fix it" code. The next lesson shows how quickly that goes wrong.
</Callout>
</Concept>

<HowItWorks title="What the DOM is">

The browser turns your HTML into a tree of objects called the **DOM** (Document Object Model). Each tag becomes a node you can find (`getElementById`), create (`createElement`), change (`textContent`) and attach (`append`). The browser redraws the screen whenever the DOM changes.

This style is called **imperative**: you give the browser step-by-step commands ("create a list item, set its text, append it"). React lets you work **declaratively** instead: you describe what the page should look like for the current data, and React works out the commands.

</HowItWorks>

<GoDeeper title="Why not just rebuild everything with innerHTML?">

You could redraw the whole cart on every change: `cartList.innerHTML = cart.map(p => "<li>" + p.name + "</li>").join("")`. That's simpler, and it's actually close to React's idea. But it throws away every element and builds new ones, so:

- anything the user typed into an input inside the list is lost, and focus jumps away;
- it's slow for big pages;
- building HTML from strings is a security risk (a product called `<img onerror=...>` would run code).

React gives you the simplicity of "redraw everything" without these problems: it compares the new description with the old one and only changes what differs.

</GoDeeper>
