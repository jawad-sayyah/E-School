In the Hooks course you fetched data in an effect, and had to handle loading, errors and race conditions yourself. Real apps also want **caching** (don't refetch the menu on every visit), **refetching** when data may be stale, **retries**, and **sharing** one request between components. **TanStack Query** (formerly React Query) does all of that.

<Concept name="useQuery" id="use-query">

You give `useQuery` a **query key** (an array that identifies the data) and a **query function** (returns a promise). It gives back the state of that data.

<ReactPlayground height={420}>

```jsx file=/App.js
import { useState } from "react";
import { QueryClient, QueryClientProvider, useQuery } from "@tanstack/react-query";
import { fetchProducts } from "./api";

function ProductList({ category }) {
  const { data, isPending, isError, error, isFetching } = useQuery({
    queryKey: ["products", category],        // a different key = a different cache entry
    queryFn: () => fetchProducts(category),
    staleTime: 30_000,                        // fresh for 30 s: no refetch when switching back
  });

  if (isPending) return <p>Loading {category}…</p>;
  if (isError) return <p className="error">Error: {error.message}</p>;
  return (
    <ul style={{ opacity: isFetching ? 0.6 : 1 }}>
      {data.map((p) => (
        <li key={p}>{p}</li>
      ))}
    </ul>
  );
}

export default function App() {
  const [queryClient] = useState(() => new QueryClient());
  const [category, setCategory] = useState("hot");
  return (
    <QueryClientProvider client={queryClient}>
      <button onClick={() => setCategory("hot")}>Hot drinks</button>{" "}
      <button onClick={() => setCategory("cold")}>Cold drinks</button>{" "}
      <button onClick={() => setCategory("broken")}>Broken category</button>
      <ProductList category={category} />
    </QueryClientProvider>
  );
}
```

```js file=/api.js
const DATA = { hot: ["Coffee", "Tea", "Hot chocolate"], cold: ["Iced coffee", "Lemonade"] };

export function fetchProducts(category) {
  return new Promise((resolve, reject) =>
    setTimeout(() => {
      if (DATA[category]) resolve(DATA[category]);
      else reject(new Error(`No category called "${category}"`));
    }, 800),
  );
}
```

```css file=/styles.css
body { font-family: system-ui, sans-serif; padding: 16px; }
.error { color: #c0392b; }
```

</ReactPlayground>

Click **Cold drinks**, then **Hot drinks** again: the hot list appears **instantly** from the cache. Try **Broken category**: TanStack Query retries a few times before showing the error.

- **`isPending`**: no data yet (first load). **`isFetching`**: a request is in flight, including background refetches.
- **`isError`** / **`error`**: the query function threw or rejected.
- The **query key** is the cache key. Put every variable the query depends on in it (`["products", category]`), like an effect's dependencies.
- One `QueryClient` holds the cache for the whole app; `QueryClientProvider` makes it available.

</Concept>

<Concept name="useMutation: changing data" id="use-mutation">

Reading is a query; creating, updating or deleting is a **mutation**. After a mutation succeeds, tell the cache which queries are now out of date, and TanStack Query refetches them:

```jsx file=AddReview.jsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

function AddReview({ productId }) {
  const queryClient = useQueryClient();
  const mutation = useMutation({
    mutationFn: (text) => postReview(productId, text),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["reviews", productId] });
    },
  });

  return (
    <form action={(formData) => mutation.mutate(formData.get("text"))}>
      <input name="text" />
      <button disabled={mutation.isPending}>{mutation.isPending ? "Posting…" : "Post"}</button>
      {mutation.isError && <p>Couldn't post: {mutation.error.message}</p>}
    </form>
  );
}
```

</Concept>

<HowItWorks title="Stale-while-revalidate">

TanStack Query treats cached data as **fresh** for `staleTime` (default 0: immediately stale). When a component asks for stale data, it gets the cached copy **at once** and a background refetch starts; when the new data arrives, components re-render. It also refetches stale queries when the window regains focus or the network reconnects. Unused data is garbage-collected after `gcTime` (5 minutes by default). Several components using the same key share **one** request and one cache entry, so there's no need to lift fetched data into context.

</HowItWorks>

<GoDeeper title="Server state vs. client state">

TanStack Query manages **server state**: data that lives on a server, that others can change, and that you only have a copy of. It isn't a general state manager. UI state (is the menu open, what's typed, the cart before checkout) still belongs in `useState`, context or a store like Zustand (two lessons from now). Separating the two removes most of what people used to put in Redux.

</GoDeeper>

<ReactExercise

`Menu` fetches with an effect and never handles errors, so a failed request leaves **Loading menu…** on screen forever. Rewrite it with `useQuery` so it shows **Loading menu…**, then the items, or **Couldn't load the menu.** when the request fails. (The tests pass a failing `fetchMenu` to check the error state; retries are already turned off.)

```jsx starter file=/App.js
import { useEffect, useState } from "react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { fetchMenu as defaultFetchMenu } from "./api";

function Menu({ fetchMenu }) {
  const [items, setItems] = useState(null);
  useEffect(() => {
    fetchMenu().then(setItems);
  }, [fetchMenu]);

  if (!items) return <p>Loading menu…</p>;
  return (
    <ul>
      {items.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default function App({ fetchMenu = defaultFetchMenu }) {
  const [client] = useState(
    () => new QueryClient({ defaultOptions: { queries: { retry: false } } }),
  );
  return (
    <QueryClientProvider client={client}>
      <Menu fetchMenu={fetchMenu} />
    </QueryClientProvider>
  );
}
```

```js starter file=/api.js
export function fetchMenu() {
  return new Promise((resolve) => setTimeout(() => resolve(["Coffee", "Tea", "Bagel"]), 100));
}
```

```jsx tests file=/App.test.js
import { act, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import App from "./App";

const wait = (ms) => act(async () => {
  await new Promise((resolve) => setTimeout(resolve, ms));
});

test("shows a loading message first", () => {
  render(<App />);
  expect(screen.getByText("Loading menu…")).toBeInTheDocument();
});

test("shows the menu items", async () => {
  render(<App />);
  await wait(300);
  expect(screen.getAllByRole("listitem").map((li) => li.textContent)).toEqual(["Coffee", "Tea", "Bagel"]);
});

test("shows an error when the request fails", async () => {
  const failing = () => Promise.reject(new Error("Server down"));
  render(<App fetchMenu={failing} />);
  await wait(100);
  expect(screen.getByText("Couldn't load the menu.")).toBeInTheDocument();
});
```

```jsx solution file=/App.js
import { useState } from "react";
import { QueryClient, QueryClientProvider, useQuery } from "@tanstack/react-query";
import { fetchMenu as defaultFetchMenu } from "./api";

function Menu({ fetchMenu }) {
  const { data, isPending, isError } = useQuery({ queryKey: ["menu"], queryFn: fetchMenu });

  if (isPending) return <p>Loading menu…</p>;
  if (isError) return <p>Couldn't load the menu.</p>;
  return (
    <ul>
      {data.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default function App({ fetchMenu = defaultFetchMenu }) {
  const [client] = useState(
    () => new QueryClient({ defaultOptions: { queries: { retry: false } } }),
  );
  return (
    <QueryClientProvider client={client}>
      <Menu fetchMenu={fetchMenu} />
    </QueryClientProvider>
  );
}
```
