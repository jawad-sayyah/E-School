Time to leave `innerHTML` behind. In React you don't update the page, you **describe** it: a component is a function that takes data (props) and returns what the page should look like. When the data changes, React works out what to change in the DOM.

This step splits the shop into two components:

- **`ProductList`** gets the `products` and an `onAdd` function, and shows a list with an **Add** button per product.
- **`Cart`** gets the cart `items`, and shows the lines and the total.

The helpers in `cartUtils.js` come along unchanged: `formatPrice`, `cartTotal`, `cartCount` and `addToCart` are plain functions, and plain functions work the same in React. (`renderCart` built HTML strings; React doesn't need it any more, so nothing calls it.)

```js starter file=/cartUtils.js
export function formatPrice(amount) {
  return "$" + amount.toFixed(2);
}

export function cartTotal(items) {
  return items.reduce((sum, item) => sum + item.price * item.qty, 0);
}

export function cartCount(items) {
  return items.reduce((sum, item) => sum + item.qty, 0);
}

export function addToCart(items, product) {
  const existing = items.find((item) => item.id === product.id);
  if (existing) {
    return items.map((item) => (item.id === product.id ? { ...item, qty: item.qty + 1 } : item));
  }
  return [...items, { ...product, qty: 1 }];
}

export function renderCart(items) {
  if (items.length === 0) return "<li>Your cart is empty.</li>";
  return items
    .map((item) => `<li>${item.name} × ${item.qty}: ${formatPrice(item.price * item.qty)}</li>`)
    .join("");
}
```

```jsx solution file=/ProductList.js
import { formatPrice } from "./cartUtils";

export default function ProductList({ products, onAdd }) {
  return (
    <section>
      <h2>Products</h2>
      <ul>
        {products.map((product) => (
          <li key={product.id}>
            {product.name} {formatPrice(product.price)}{" "}
            <button aria-label={`Add ${product.name}`} onClick={() => onAdd(product)}>
              Add
            </button>
          </li>
        ))}
      </ul>
    </section>
  );
}
```

<HowItWorks title="What React does with your JSX">

`<Cart items={cart} />` doesn't create DOM nodes. It creates a small object, `{ type: Cart, props: { items: cart } }`. React calls `Cart(props)`, gets more of these objects back (a `section`, an `h2`, a `ul`…), and builds the real DOM from the whole tree once.

On later renders React builds the new tree, compares it with the previous one, and changes only the DOM nodes that differ. That's why `key` matters in lists: it tells React which `<li>` is which item, so adding an item to the top doesn't make it rewrite every line.

And text is always **escaped**: a product called `<img onerror=…>` shows up as that text, not as an image tag, unlike `innerHTML`.

</HowItWorks>
