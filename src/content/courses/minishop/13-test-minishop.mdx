You've written a "Test it" in almost every step. Now it's time to look at MiniShop's tests as one **suite**, the way a team would before calling the shop done. A good suite is shaped like a pyramid:

| Layer | What | How many | Speed |
| --- | --- | --- | --- |
| **Unit** | Pure logic: `cartReducer`, `cartUtils`, `storage` | Many | Milliseconds |
| **Integration** | Components with their real hooks and context: `Cart`, `ProductList`, the checkout form | Some | Tens of milliseconds |
| **End-to-end** | The real app in a real browser: the checkout flow | One or two | Seconds |

Every layer catches different bugs. Unit tests pin down the rules. Integration tests prove the pieces work together the way a user uses them. The E2E test proves the built site works, routing, storage and all.

## Unit: cartReducer

The reducer holds every rule of the cart, so it gets the most tests. They're plain function calls: no rendering, no waiting.

```ts code file=/cartReducer.ts
import { addToCart } from "./cartUtils";
import type { CartAction, CartItem } from "./types";

export function cartReducer(items: CartItem[], action: CartAction): CartItem[] {
  switch (action.type) {
    case "add":
      return addToCart(items, action.product);
    case "remove":
      return items.filter((item) => item.id !== action.id);
    case "setQty":
      if (action.qty < 1) return items.filter((item) => item.id !== action.id);
      return items.map((item) => (item.id === action.id ? { ...item, qty: action.qty } : item));
    case "clear":
      return [];
    default: {
      const unhandled: never = action;
      throw new Error(`Unknown action: ${JSON.stringify(unhandled)}`);
    }
  }
}
```

```ts code file=/cartUtils.ts
import type { CartItem, Product } from "./types";

export function formatPrice(amount: number): string {
  return "$" + amount.toFixed(2);
}

export function cartTotal(items: CartItem[]): number {
  return items.reduce((sum, item) => sum + item.price * item.qty, 0);
}

export function cartCount(items: CartItem[]): number {
  return items.reduce((sum, item) => sum + item.qty, 0);
}

export function addToCart(items: CartItem[], product: Product): CartItem[] {
  const existing = items.find((item) => item.id === product.id);
  if (existing) {
    return items.map((item) => (item.id === product.id ? { ...item, qty: item.qty + 1 } : item));
  }
  return [...items, { ...product, qty: 1 }];
```
```ts bug file=/cartReducer.ts title="clear does nothing" hint="Clear a cart that has items."
}
```

```ts solution file=/cartReducer.test.ts
import { describe, expect, test } from "vitest";
import { cartReducer } from "./cartReducer";
import type { CartItem, Product } from "./types";

const tea: Product = { id: 2, name: "Green tea", price: 8 };
const mug: Product = { id: 3, name: "Travel mug", price: 15 };
const cart: CartItem[] = [
  { ...tea, qty: 1 },
  { ...mug, qty: 2 },
];

describe("cartReducer", () => {
  test("add: a new product gets qty 1, an existing one gets +1", () => {
    expect(cartReducer([], { type: "add", product: tea })).toEqual([{ ...tea, qty: 1 }]);
    expect(cartReducer(cart, { type: "add", product: tea })).toEqual([
      { ...tea, qty: 2 },
      { ...mug, qty: 2 },
    ]);
  });

  test("remove takes out one line", () => {
    expect(cartReducer(cart, { type: "remove", id: 2 })).toEqual([{ ...mug, qty: 2 }]);
  });

  test("setQty changes only that line, and 0 removes it", () => {
    expect(cartReducer(cart, { type: "setQty", id: 3, qty: 5 })).toEqual([
      { ...tea, qty: 1 },
      { ...mug, qty: 5 },
    ]);
    expect(cartReducer(cart, { type: "setQty", id: 2, qty: 0 })).toEqual([{ ...mug, qty: 2 }]);
  });

  test("clear empties the cart", () => {
    expect(cartReducer(cart, { type: "clear" })).toEqual([]);
  });
});
```

```tsx code file=/CartContext.tsx
import {
  createContext,
  useContext,
  useEffect,
  useReducer,
  type Dispatch,
  type ReactNode,
} from "react";
import { cartReducer } from "./cartReducer";
import { cartCount, cartTotal } from "./cartUtils";
import { loadCart, saveCart } from "./storage";
import type { CartAction, CartItem, Product } from "./types";

interface CartContextValue {
  items: CartItem[];
  dispatch: Dispatch<CartAction>;
}

const CartContext = createContext<CartContextValue | null>(null);

export function CartProvider({ children }: { children: ReactNode }) {
  const [items, dispatch] = useReducer(cartReducer, undefined, loadCart);

  useEffect(() => {
    saveCart(items);
  }, [items]);

  return <CartContext value={{ items, dispatch }}>{children}</CartContext>;
}

export function useCart() {
  const context = useContext(CartContext);
  if (!context) throw new Error("useCart must be used inside <CartProvider>");
  const { items, dispatch } = context;
  return {
    items,
    count: cartCount(items),
    total: cartTotal(items),
    add: (product: Product) => dispatch({ type: "add", product }),
    remove: (id: number) => dispatch({ type: "remove", id }),
    setQty: (id: number, qty: number) => dispatch({ type: "setQty", id, qty }),
    clear: () => dispatch({ type: "clear" }),
  };
}
```

```ts code file=/storage.ts
import type { CartItem } from "./types";

const KEY = "minishop-cart";

export function loadCart(): CartItem[] {
  try {
    const saved: unknown = JSON.parse(localStorage.getItem(KEY) ?? "null");
    return Array.isArray(saved) ? (saved as CartItem[]) : [];
  } catch {
    return [];
  }
}

export function saveCart(items: CartItem[]): void {
  try {
    localStorage.setItem(KEY, JSON.stringify(items));
  } catch {
    // Storage is full or blocked (private mode): the cart still works, it just isn't saved.
  }
}
```

```tsx starter file=/shop.test.tsx
import { fireEvent, render, screen } from "@testing-library/react";
import "@testing-library/jest-dom";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { createMemoryRouter, RouterProvider } from "react-router";
import { afterEach, beforeEach, expect, test, vi } from "vitest";
import Cart from "./Cart";
import ProductList from "./ProductList";
import { CartProvider } from "./CartContext";
import { api } from "./api";
import { products } from "./products";

function renderShop() {
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  const router = createMemoryRouter([{ path: "/", element: <><ProductList /><Cart /></> }]);
  render(
    <QueryClientProvider client={client}>
      <CartProvider>
        <RouterProvider router={router} />
      </CartProvider>
    </QueryClientProvider>,
  );
}

beforeEach(() => {
  localStorage.clear();
  vi.spyOn(api, "fetchProducts").mockResolvedValue(products);
});
afterEach(() => vi.restoreAllMocks());

test("Add puts a product in the cart", async () => {
  renderShop();
  fireEvent.click(await screen.findByRole("button", { name: "Add Green tea" }));
  expect(screen.getByText("Green tea × 1: $8.00")).toBeInTheDocument();
});
```

## Mocking the real API with MSW

Our `api.fetchProducts` is a pretend server, so the tests replace it with `vi.spyOn`. A real shop calls `fetch`:

```ts file=api.ts
export const api = {
  async fetchProducts(): Promise<Product[]> {
    const response = await fetch("/api/products");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  },
};
```

Then the best place to mock is the **network**, with MSW (Mock Service Worker): the code under test runs exactly as in production, including `fetch`, the status check and the JSON parsing. MSW needs Node's network layer (or a real service worker), so it can't run inside this page's sandbox; here is the test and what a run prints.

```tsx file=src/ProductList.msw.test.tsx
import { http, HttpResponse } from "msw";
import { setupServer } from "msw/node";
import { afterAll, afterEach, beforeAll, expect, test } from "vitest";
import { screen } from "@testing-library/react";
import { products } from "./products";
import { renderShop } from "./test-utils";

const server = setupServer(http.get("/api/products", () => HttpResponse.json(products)));

beforeAll(() => server.listen({ onUnhandledRequest: "error" }));
afterEach(() => server.resetHandlers());
afterAll(() => server.close());

test("shows the products from the API", async () => {
  renderShop();
  expect(await screen.findByRole("link", { name: "Green tea" })).toBeInTheDocument();
});

test("a server error shows the error and Try again", async () => {
  server.use(http.get("/api/products", () => new HttpResponse(null, { status: 500 })));
  renderShop();
  expect(await screen.findByRole("alert")).toHaveTextContent("Couldn't load the products.");
});
```

## Accessibility with jest-axe

```tsx file=src/checkout.a11y.test.tsx
import { axe } from "jest-axe";
```

<HowItWorks title="Why not test everything end to end?">

An E2E test touches everything, which is exactly why it's expensive: it needs a build, a server and a browser, takes seconds instead of milliseconds, and when it fails it tells you *that* something broke, not *what*. A reducer bug shows up in the E2E test as "Place order didn't show the thank-you text", and you still have to go looking.

The same bug in a unit test says "`setQty` with `0` returned a line with qty 0". That's why the pyramid has many fast, precise tests at the bottom and only a few slow, broad ones at the top. Each layer is there to catch what the layer below can't: the integration tests catch wiring mistakes the unit tests can't see, and the E2E test catches build, routing and browser problems that jsdom never has.

</HowItWorks>
