The cart reducer from the Hooks course is the perfect place for TypeScript's discriminated unions: each action has a `type` tag and its own data, and the reducer's `switch` narrows to each one.

<Concept name="State and actions" id="types">

<TSPlayground file="cartReducer.tsx" errors={[31, 32]} checkOnly>

```tsx
import { useReducer } from "react";

type Product = { id: number; name: string; price: number };
type CartLine = Product & { qty: number };

type CartAction =
  | { type: "added"; product: Product }
  | { type: "removed"; id: number }
  | { type: "qtyChanged"; id: number; qty: number }
  | { type: "emptied" };

function cartReducer(cart: CartLine[], action: CartAction): CartLine[] {
  switch (action.type) {
    case "added": {
      const line = cart.find((l) => l.id === action.product.id);   // action: the "added" member
      return line
        ? cart.map((l) => (l === line ? { ...l, qty: l.qty + 1 } : l))
        : [...cart, { ...action.product, qty: 1 }];
    }
    case "removed":
      return cart.filter((l) => l.id !== action.id);
    case "qtyChanged":
      return cart.map((l) => (l.id === action.id ? { ...l, qty: action.qty } : l));
    case "emptied":
      return [];
  }
}

function Cart() {
  const [cart, dispatch] = useReducer(cartReducer, []);
  dispatch({ type: "removed" });                     // error: id is missing
  dispatch({ type: "remove", id: 1 });               // error: no such action
  return <button onClick={() => dispatch({ type: "emptied" })}>Empty ({cart.length})</button>;
}
```

</TSPlayground>

- `useReducer(cartReducer, [])` infers the state (`CartLine[]`) and the action type from the reducer: `dispatch` only accepts `CartAction`s.
- Inside each `case`, `action` is narrowed: `action.product` only exists for `"added"`.
- Because the `switch` covers every member, TypeScript knows the function always returns. Add a new action and forget its case, and you get "not all code paths return a value".

</Concept>

<Concept name="Passing dispatch down" id="dispatch">

Type it with `Dispatch<CartAction>` (from `"react"`):

```tsx file=AddButton.tsx
import type { Dispatch } from "react";

function AddButton({ product, dispatch }: { product: Product; dispatch: Dispatch<CartAction> }) {
  return <button onClick={() => dispatch({ type: "added", product })}>Add {product.name}</button>;
}
```

Or keep `dispatch` inside a context and expose small, named functions (`add`, `remove`) through a custom hook, as the next lessons do.

</Concept>

<HowItWorks title="Why the discriminated union matters here">

With a loose action type like `{ type: string; payload?: any }`, every dispatch compiles, typos included, and the reducer has to guess what's in `payload`. With a union, the **type tag** decides which data must be present, the editor autocompletes action names, and refactors (renaming `"added"`) update or flag every dispatch. It's the same benefit Redux Toolkit gives you automatically with `createSlice`.

</HowItWorks>

<TSExercise
  id="type-cart-actions"
  title="Type the cart actions"
  hints={[
    "`type CartAction = { type: \"added\"; product: Product } | { type: \"removed\"; id: number } | { type: \"emptied\" };`",

Replace the loose `action: any` with a `CartAction` discriminated union for `"added"` (with a `product`), `"removed"` (with an `id`) and `"emptied"`, and type the reducer's state and return value.

```tsx starter
type Product = { id: number; name: string; price: number };
type CartLine = Product & { qty: number };

type CartAction = any;

function cartReducer(cart, action: CartAction) {
  switch (action.type) {
    case "added":
      return [...cart, { ...action.product, qty: 1 }];
    case "removed":
      return cart.filter((l) => l.id !== action.id);
    case "emptied":
      return [];
  }
}
```

```tsx types
const tea: Product = { id: 1, name: "Tea", price: 2 };
const next: CartLine[] = cartReducer([], { type: "added", product: tea });
cartReducer(next, { type: "removed", id: 1 });
cartReducer(next, { type: "emptied" });
// @ts-expect-error "removed" needs an id
cartReducer(next, { type: "removed" });
// @ts-expect-error there's no "cleared" action
cartReducer(next, { type: "cleared" });
// @ts-expect-error the cart is a list of cart lines
cartReducer(["Tea"], { type: "emptied" });
```
