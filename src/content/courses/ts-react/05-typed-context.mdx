`createContext<T>(defaultValue)` is generic too. The question is what to use as the default when the real value only exists inside a provider.

<Concept name="The null default and a guarding hook" id="pattern">

<TSPlayground file="CartContext.tsx" errors={[25]} checkOnly>

```tsx
import { createContext, useContext, useState, type ReactNode } from "react";

type CartContextValue = {
  count: number;
  add: () => void;
};

const CartContext = createContext<CartContextValue | null>(null);

export function CartProvider({ children }: { children: ReactNode }) {
  const [count, setCount] = useState(0);
  const add = () => setCount((c) => c + 1);
  return <CartContext value={{ count, add }}>{children}</CartContext>;
}

export function useCart(): CartContextValue {
  const value = useContext(CartContext);
  if (!value) throw new Error("useCart must be used inside <CartProvider>");
  return value;                                   // narrowed: CartContextValue
}

function Badge() {
  const { count } = useCart();                    // no null check needed here
  const raw = useContext(CartContext);
  return <span>{count} {raw.count}</span>;        // error: raw may be null
}
```

</TSPlayground>

1. Type the context as `T | null` with a `null` default: honest, since there's no value outside a provider.
2. A custom hook checks for `null` once and throws a helpful error; its return type is plain `T`.
3. Components call the hook, never `useContext(CartContext)` directly.

</Concept>

<Concept name="Why not a fake default?" id="fake">

```tsx file=bad.tsx
const CartContext = createContext<CartContextValue>({ count: 0, add: () => {} });
```

It type-checks, but a component rendered outside the provider silently gets the fake value: the badge shows 0 forever, and "Add" does nothing. The `null` default plus the throwing hook turns that silent bug into an immediate, clear error. A real default only makes sense when it's genuinely useful (a theme context that defaults to `"light"`).

</Concept>

<HowItWorks title="Typing the value object">

The value type is just an object type, so you can derive it: `type CartContextValue = ReturnType<typeof useCartState>` if a custom hook builds the value, or list it explicitly when it's the context's public API (explicit is clearer for teammates). If the value is rebuilt on every render, wrap it in `useMemo` for performance; the type doesn't change.

</HowItWorks>

Type the user context the safe way: the context is `UserContextValue | null` with a `null` default, and `useUser()` throws outside the provider and returns a plain `UserContextValue`.

```tsx starter
import { createContext, useContext, useState, type ReactNode } from "react";

type User = { id: number; name: string };
type UserContextValue = { user: User | null; signIn: (user: User) => void; signOut: () => void };

const UserContext = createContext(null);

export function UserProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const value = { user, signIn: setUser, signOut: () => setUser(null) };
  return <UserContext value={value}>{children}</UserContext>;
}

export function useUser() {
  return useContext(UserContext);
}
```

```tsx types
function Greeting() {
  const { user, signOut } = useUser();
  return <p onClick={signOut}>{user ? user.name : "Guest"}</p>;
}
function SignIn() {
  const { signIn } = useUser();
  // @ts-expect-error signIn needs a full user
  signIn({ name: "Ada" });
  return null;
}
```

}

  const value = useContext(UserContext);
  if (!value) throw new Error("useUser must be used inside <UserProvider>");
  return value;
}
