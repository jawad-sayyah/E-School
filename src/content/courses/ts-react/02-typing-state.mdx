`useState` is generic: `useState<T>(initial)`. For simple values TypeScript infers `T` from the initial value. You only write it yourself when the initial value doesn't tell the whole story.

<Concept name="When inference is enough" id="inferred">

<TSPlayground file="Counter.tsx" errors={[7, 8]} checkOnly>

```tsx
import { useState } from "react";

function Counter() {
  const [qty, setQty] = useState(1);           // number
  const [note, setNote] = useState("");        // string
  const [open, setOpen] = useState(false);     // boolean
  setQty("2");                                 // error: not a number
  setOpen("yes");                              // error: not a boolean
  setQty((q) => q + 1);                        // q is a number
  return <button onClick={() => setNote(note + "!")}>{qty}</button>;
}
```

</TSPlayground>

</Concept>

<Concept name="When you must say it" id="explicit">

Three common cases where the initial value is too narrow or too vague:

<TSPlayground file="Cart.tsx" errors={[10]} checkOnly>

```tsx
import { useState } from "react";

type CartLine = { id: number; name: string; qty: number };
type User = { id: number; name: string };

function Cart() {
  // 1. An empty array: without <CartLine[]> it would be never[]
  const [lines, setLines] = useState<CartLine[]>([]);
  const [broken, setBroken] = useState([]);
  setBroken([{ id: 1, name: "Tea", qty: 1 }]);           // error: never[] accepts nothing

  // 2. "Nothing yet": the value starts as null
  const [user, setUser] = useState<User | null>(null);

  // 3. A union of states
  const [status, setStatus] = useState<"idle" | "saving" | "saved">("idle");

  setLines([...lines, { id: 1, name: "Tea", qty: 1 }]);
  setStatus("saving");
  return <p>{user ? `Hi ${user.name}` : "Sign in"} · {lines.length} · {status}</p>;
}
```

</TSPlayground>

- With `useState<User | null>(null)`, TypeScript makes you check `user` before reading `user.name`: no more "Cannot read properties of null" crashes.
- For a union like `status`, the type argument also stops typos: `setStatus("saved!")` is an error.

</Concept>

<HowItWorks title="What setState's type looks like">

`useState<T>` returns `[T, Dispatch<SetStateAction<T>>]`. `SetStateAction<T>` is `T | ((prev: T) => T)`: a new value or an updater function. So both `setQty(2)` and `setQty((q) => q + 1)` are checked, and in the updater, `q` is already typed. If you pass state setters down as props, type them as `(value: number) => void` (simple) or `Dispatch<SetStateAction<number>>` (when the child also needs the updater form).

</HowItWorks>

The `useWishlist` hook keeps three pieces of state. Give each `useState` the right type: `items` is a list of `WishItem` (starts empty), `selected` is a `WishItem` or nothing yet, and `view` is `"grid"` or `"list"`.

```tsx starter
import { useState } from "react";

type WishItem = { id: number; name: string };

export function useWishlist() {
  const [items, setItems] = useState([]);
  const [selected, setSelected] = useState(null);
  const [view, setView] = useState("grid");

  function add(item: WishItem) {
    setItems([...items, item]);
    setSelected(item);
  }

  return { items, selected, view, setView, add };
}
```

```tsx types
const w = useWishlist();
const names: string[] = w.items.map((i) => i.name);
const selectedName: string | undefined = w.selected?.name;
w.setView("list");
w.add({ id: 1, name: "Tea" });
// @ts-expect-error the view is only "grid" or "list"
w.setView("tiles");
// @ts-expect-error selected may be null, so check it first
w.selected.name;
// @ts-expect-error items are WishItems
w.items.push("Tea");
```

```tsx solution
import { useState } from "react";

type WishItem = { id: number; name: string };

export function useWishlist() {
  const [items, setItems] = useState<WishItem[]>([]);
  const [selected, setSelected] = useState<WishItem | null>(null);
  const [view, setView] = useState<"grid" | "list">("grid");

  function add(item: WishItem) {
    setItems([...items, item]);
    setSelected(item);
  }

  return { items, selected, view, setView, add };
}
```
