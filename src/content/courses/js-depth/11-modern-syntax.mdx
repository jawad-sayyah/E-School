JavaScript gets new features every year. These are the ones you'll actually meet in modern React code and libraries, each replacing a clumsier older pattern.

<Concept name="??=  ||=  &&=" id="logical-assignment">

Logical assignment sets a value only when needed: `??=` if it's null or undefined, `||=` if it's falsy, `&&=` if it's truthy.

<Playground file="logical.js" expected={["{ theme: 'dark', qty: 1, coupon: 'SAVE10' }"]}>

```js
const settings = { theme: null, qty: 0, coupon: "save10" };

settings.theme ??= "dark";               // was null
settings.qty ||= 1;                      // 0 is falsy
settings.coupon &&= settings.coupon.toUpperCase();

console.log(settings);
```

</Playground>
</Concept>

<Concept name="at()" id="at">

`at()` reads by position and accepts negative numbers to count from the end.

<Playground file="at.js" expected={["Muffin Muffin", "e"]}>

```js
const cart = ["Coffee", "Bagel", "Muffin"];

console.log(cart.at(-1), cart[cart.length - 1]);   // same, shorter
console.log("Coffee".at(-1));
```

</Playground>
</Concept>

<Concept name="toSorted(), toReversed(), with()" id="copying-methods" react>

These are the copying versions of `sort`, `reverse` and index assignment: they return a new array and never touch the original, which is exactly what React state needs.

<Playground file="copying.js" expected={["[ 1, 3, 5 ]", "[ 3, 1, 5 ]", "[ 9, 1, 3 ]", "[ 5, 1, 3 ]"]}>

```js
const prices = [5, 1, 3];

console.log(prices.toSorted((a, b) => a - b));
console.log(prices.toReversed());
console.log(prices.with(0, 9));
console.log(prices);   // unchanged
```

</Playground>
</Concept>

<Concept name="Object.groupBy()" id="group-by">

`Object.groupBy` sorts items into groups by a key you choose, replacing a hand-written `reduce`.

<Playground file="group-by.js" expected={["[ 'Tea', 'Coffee' ]", "[ 'drink', 'food' ]"]}>

```js
const items = [
  { name: "Tea", type: "drink" },
  { name: "Bagel", type: "food" },
  { name: "Coffee", type: "drink" },
];

const groups = Object.groupBy(items, (item) => item.type);
console.log(groups.drink.map((item) => item.name));
console.log(Object.keys(groups));
```

</Playground>
</Concept>

<Concept name="Array.from()" id="array-from">

`Array.from` builds an array from anything list-like, with an optional function to fill it.

<Playground file="from.js" expected={["[ 0, 2, 4 ]", "[ 'T', 'e', 'a' ]"]}>

```js
console.log(Array.from({ length: 3 }, (_, i) => i * 2));
console.log(Array.from("Tea"));
```

</Playground>
</Concept>

<Concept name="padStart() & numeric separators" id="pad-start">

`padStart` pads text to a fixed width, and `_` in number literals makes big numbers readable.

<Playground file="pad.js" expected={["ORDER-00042", "1000000"]}>

```js
console.log(`ORDER-${String(42).padStart(5, "0")}`);
console.log(1_000_000);
```

</Playground>
</Concept>

<Concept name="Promise.allSettled()" id="all-settled">

`Promise.allSettled` waits for every promise and tells you which worked, instead of failing as soon as one fails like `Promise.all`.

<Playground file="all-settled.js" expected={["[ 'fulfilled', 'rejected' ]", "no"]}>

```js
const results = await Promise.allSettled([
  Promise.resolve("ok"),
  Promise.reject(new Error("no")),
]);

console.log(results.map((r) => r.status));
console.log(results[1].reason.message);
```

</Playground>
</Concept>

<GoDeeper title="How new features reach your users">

New JavaScript features go through the **TC39** committee in stages 0 to 4; stage 4 means they're in the yearly standard (ES2023, ES2024…). Browsers ship them over the following months.

To use a feature in an app today, check its support on caniuse.com or MDN. Tools like Vite can **transpile** newer syntax for older browsers, and **polyfills** can add missing functions such as `Object.groupBy`. This site uses all the features in this lesson, because every current browser supports them.

</GoDeeper>

<Exercise
  id="top-products"
  title="The most expensive products"
  hints={[
    "Sort a copy by price, highest first: `products.toSorted((a, b) => b.price - a.price)`.",
    "Take the first `n` with `slice(0, n)` and map them to names.",
  ]}
>

Write `topProducts(products, n)` that returns the names of the `n` most expensive products, most expensive first, without changing the original array.

```js starter
function topProducts(products, n) {
  products.sort((a, b) => b.price - a.price);
  return products.slice(0, n).map((p) => p.name);
}
```

```js tests
const list = () => [
  { name: "Tea", price: 2 },
  { name: "Cake", price: 6 },
  { name: "Coffee", price: 4 },
];

test("returns the most expensive first", () => {
  expect(topProducts(list(), 2)).toEqual(["Cake", "Coffee"]);
});

test("does not change the original array", () => {
  const products = list();
  topProducts(products, 2);
  expect(products[0].name).toBe("Tea");
});

test("n larger than the list returns everything", () => {
  expect(topProducts(list(), 10)).toHaveLength(3);
});
```

```js solution
function topProducts(products, n) {
  return products
    .toSorted((a, b) => b.price - a.price)
    .slice(0, n)
    .map((p) => p.name);
}
```

</Exercise>
