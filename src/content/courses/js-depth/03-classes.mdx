A **class** is a blueprint for objects that share the same shape and behavior. You'll meet classes in libraries, error types and older React code, even if modern React components are functions.

<Concept name="class & constructor" id="class-constructor">

`new` creates an object from the class, and `constructor` sets up its starting data.

<Playground file="class.js" expected={["Item { name: 'Coffee', price: 4 }"]}>

```js
class Item {
  constructor(name, price) {
    this.name = name;
    this.price = price;
  }
}

const coffee = new Item("Coffee", 4);
console.log(coffee);
```

</Playground>
</Concept>

<Concept name="Methods" id="methods">

Methods are functions every object of the class shares. Returning `this` lets you chain calls.

<Playground file="methods.js" expected={["7"]}>

```js
class Cart {
  constructor() {
    this.items = [];
  }
  add(item) {
    this.items.push(item);
    return this;
  }
  total() {
    return this.items.reduce((sum, i) => sum + i.price, 0);
  }
}

const cart = new Cart().add({ price: 4 }).add({ price: 3 });
console.log(cart.total());
```

</Playground>
</Concept>

<Concept name="get & set" id="getters">

A getter looks like a property but runs code every time you read it, which is ideal for derived values.

<Playground file="getter.js" expected={["6", "10"]}>

```js
class Line {
  constructor(price, qty) {
    this.price = price;
    this.qty = qty;
  }
  get total() {
    return this.price * this.qty;
  }
}

const tea = new Line(2, 3);
console.log(tea.total);
tea.qty = 5;
console.log(tea.total);   // always up to date
```

</Playground>
</Concept>

<Concept name="static" id="static">

`static` members belong to the class itself, not to each object, which suits helpers and counters.

<Playground file="static.js" expected={["$4.50"]}>

```js
class Price {
  static format(n) {
    return `$${n.toFixed(2)}`;
  }
}

console.log(Price.format(4.5));
```

</Playground>
</Concept>

<Concept name="#private fields" id="private-fields">

Fields starting with `#` can only be used inside the class, so outside code can't change them by accident.

<Playground file="private.js" expected={["20", "true []"]}>

```js
class Wallet {
  #balance = 0;
  deposit(amount) {
    this.#balance += amount;
  }
  get balance() {
    return this.#balance;
  }
}

const wallet = new Wallet();
wallet.deposit(20);
console.log(wallet.balance);
console.log(wallet.balance === 20, Object.keys(wallet));
```

</Playground>
</Concept>

<Concept name="extends & super" id="extends">

`extends` builds a class on top of another; `super` calls the parent's constructor or methods.

<Playground file="extends.js" expected={["Mug: $10 (-20%)"]}>

```js
class Product {
  constructor(name, price) {
    this.name = name;
    this.price = price;
  }
  label() {
    return `${this.name}: $${this.price}`;
  }
}

class SaleProduct extends Product {
  constructor(name, price, off) {
    super(name, price);       // run Product's constructor first
    this.off = off;
  }
  label() {
    return `${super.label()} (-${this.off}%)`;
  }
}

console.log(new SaleProduct("Mug", 10, 20).label());
```

</Playground>
</Concept>

<Concept name="Forgetting new" id="forgetting-new" warn>

Calling a class without `new` is an error, unlike old constructor functions.

<Playground file="no-new.js" expected={["Uncaught TypeError: Class constructor Item cannot be invoked without 'new'"]}>

```js
class Item {}
const tea = Item();
```

</Playground>
</Concept>

<GoDeeper title="Class fields and arrow methods">

You can declare fields right in the class body, and an **arrow function field** keeps `this` bound to the object, which is handy for callbacks:

<Playground file="fields.js" expected={["1", "2"]}>

```js
class Counter {
  count = 0;                         // a field with a starting value
  increment = () => ++this.count;    // `this` is always this counter
}

const counter = new Counter();
const inc = counter.increment;       // pass it around…
console.log(inc());
console.log(inc());                  // …it still works
```

</Playground>

The cost: each object gets its own copy of the arrow function, while normal methods are shared on the prototype (next lesson).

</GoDeeper>

<Exercise
  id="cart-class"
  title="A Cart class"
  hints={[
    "Start with `items = [];` as a field, or set `this.items = []` in the constructor.",
    "`remove(id)` can replace `this.items` with a filtered array.",
    "Make `total` and `count` getters: `get total() { … }`.",
  ]}
>

Write a `Cart` class with `add(item)`, `remove(id)`, and two getters: `total` (sum of `price * qty`) and `count` (sum of `qty`). Items look like `{ id: 1, price: 4, qty: 2 }`.

```js starter
class Cart {
  // your code here
}

const cart = new Cart();
cart.add({ id: 1, price: 4, qty: 2 });
console.log(cart.total);
```

```js tests
test("starts empty", () => {
  const cart = new Cart();
  expect(cart.total).toBe(0);
  expect(cart.count).toBe(0);
});

test("adds items", () => {
  const cart = new Cart();
  cart.add({ id: 1, price: 4, qty: 2 });
  cart.add({ id: 2, price: 3, qty: 1 });
  expect(cart.total).toBe(11);
  expect(cart.count).toBe(3);
});

test("removes items by id", () => {
  const cart = new Cart();
  cart.add({ id: 1, price: 4, qty: 2 });
  cart.add({ id: 2, price: 3, qty: 1 });
  cart.remove(1);
  expect(cart.total).toBe(3);
});

test("each cart has its own items", () => {
  const a = new Cart();
  const b = new Cart();
  a.add({ id: 1, price: 4, qty: 1 });
  expect(b.count).toBe(0);
});
```

```js solution
class Cart {
  items = [];
  add(item) {
    this.items.push(item);
  }
  remove(id) {
    this.items = this.items.filter((item) => item.id !== id);
  }
  get total() {
    return this.items.reduce((sum, item) => sum + item.price * item.qty, 0);
  }
  get count() {
    return this.items.reduce((n, item) => n + item.qty, 0);
  }
}

const cart = new Cart();
cart.add({ id: 1, price: 4, qty: 2 });
console.log(cart.total);
```

</Exercise>
