JavaScript has **one** call stack, so it does one thing at a time. Timers, clicks and network replies wait in queues until the stack is free. The **event loop** is the rule that decides what runs next. Once you can picture it, async ordering questions become easy.

<Concept name="One call stack" id="call-stack">

Functions run on a stack: a call goes on top, and when it returns it comes off, so the caller continues where it left off.

<Playground file="stack.js" expected={["in a", "in b", "back in a"]}>

```js
function a() {
  console.log("in a");
  b();                       // a waits while b runs on top of it
  console.log("back in a");
}

function b() {
  console.log("in b");
}

a();
```

</Playground>
</Concept>

<Concept name="Long code blocks everything" id="blocking" warn>

While code is running, nothing else can: not timers, not clicks, not screen updates. A slow loop freezes the page.

<Playground file="blocking.js" expected={["loop done", "timer ran after 300+ ms"]}>

```js
const start = Date.now();

setTimeout(() => {
  const waited = Date.now() - start;
  console.log("timer ran after", waited >= 300 ? "300+ ms" : "less");
}, 0);

while (Date.now() - start < 300) {}   // busy for 300 ms
console.log("loop done");
```

</Playground>
</Concept>

<Concept name="Tasks: timers and events" id="tasks">

When a timer finishes or the user clicks, the callback goes into the **task queue**. One task runs at a time, only when the stack is empty.

<Playground file="tasks.js" expected={["sync", "0 ms", "100 ms"]}>

```js
setTimeout(() => console.log("100 ms"), 100);
setTimeout(() => console.log("0 ms"), 0);
console.log("sync");
```

</Playground>
</Concept>

<Concept name="Microtasks: promise callbacks go first" id="microtasks" react>

Promise callbacks (and code after `await`) go into the **microtask queue**, and the whole microtask queue empties before the next task.

<Playground file="micro.js" expected={["start", "end", "promise", "timeout"]}>

```js
console.log("start");
setTimeout(() => console.log("timeout"), 0);
Promise.resolve().then(() => console.log("promise"));
console.log("end");
```

</Playground>

<Concept name="await splits a function" id="await-splits" react>

Everything after an `await` runs later, as a microtask, so the code that called the async function carries on first.

<Playground file="await.js" expected={["1", "2", "3", "4"]}>

```js
async function load() {
  console.log("2");
  await null;               // the rest of load() waits in the microtask queue
  console.log("4");
}

console.log("1");
load();
console.log("3");
```

</Playground>
</Concept>

<GoDeeper title="The event loop algorithm, and where rendering fits">

The browser repeats this forever:

1. Take **one** task from the task queue and run it (the first task is your script).
2. Run **every** microtask, including any new ones added while running them.
3. If it's time (about 60 times a second), **update the screen**: run `requestAnimationFrame` callbacks, recalculate styles and layout, and paint.
4. Go back to 1.

Two consequences:

- A microtask that keeps adding microtasks starves everything: no tasks, no painting. It's as bad as an infinite loop.
- The screen can only update **between** tasks. If a click handler runs for 2 seconds, the page is frozen for 2 seconds. Long work belongs in smaller chunks or a Web Worker. (This site runs your code in a Web Worker for exactly that reason.)

</GoDeeper>

<Exercise
  id="run-in-order"
  title="Run async tasks one after another"
  hints={[
    "`Promise.all` starts every task at once; here each must wait for the one before.",
    "Use a `for...of` loop and `await` each task inside it.",
    "Collect each result in an array and return it.",
  ]}
>

Write `async function runInOrder(tasks)`. `tasks` is an array of functions that return promises. Run them **one at a time**, in order, and return an array of their results.

```js starter
async function runInOrder(tasks) {
  return Promise.all(tasks.map((task) => task()));
}
```

```js tests
const delayed = (ms, value, log) => () =>
  new Promise((resolve) =>
    setTimeout(() => {
      log.push(value);
      resolve(value);
    }, ms),
  );

test("returns the results in order", async () => {
  const log = [];
  const results = await runInOrder([delayed(30, "a", log), delayed(5, "b", log)]);
  expect(results).toEqual(["a", "b"]);
});

test("waits for each task before starting the next", async () => {
  const log = [];
  await runInOrder([delayed(30, "slow", log), delayed(5, "fast", log)]);
  expect(log).toEqual(["slow", "fast"]);
});

test("an empty list gives an empty array", async () => {
  expect(await runInOrder([])).toEqual([]);
});
```

```js solution
async function runInOrder(tasks) {
  const results = [];
  for (const task of tasks) {
    results.push(await task());
  }
  return results;
}
```

</Exercise>
