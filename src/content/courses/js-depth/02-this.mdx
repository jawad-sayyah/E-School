`this` is a special name that points at an object, but **which** object depends on how the function is called, not where it's written. Arrow functions are the one exception.

<Concept name="this in a method" id="this-method">

When you call a function as `object.method()`, `this` inside it is that object.

<Playground file="method.js" expected={["2"]}>

```js
const cart = {
  items: ["Coffee", "Tea"],
  count() {
    return this.items.length;
  },
};

console.log(cart.count());
```

</Playground>
</Concept>

<Concept name="Losing this" id="losing-this" warn react>

Take a method off its object and call it on its own, and `this` is no longer the object.

<Playground file="lost.js" expected={["Uncaught TypeError: Cannot read properties of undefined (reading 'length')"]}>

```js
const cart = {
  items: ["Coffee"],
  count() {
    return this.items.length;
  },
};

const count = cart.count;   // just the function, no object attached
console.log(count());
```

</Playground>

<Callout type="react">
This used to bite every React class component: `onClick={this.handleClick}` lost `this`. Function components and hooks don't use `this` at all, which is one reason they took over.
</Callout>
</Concept>

<Concept name="bind()" id="bind">

`bind` makes a new function with `this` locked to the object you give it, so it can be passed around safely.

<Playground file="bind.js" expected={["1"]}>

```js
const cart = {
  items: ["Coffee"],
  count() {
    return this.items.length;
  },
};

const count = cart.count.bind(cart);
console.log(count());
```

</Playground>
</Concept>

<Concept name="Arrow functions keep the outer this" id="arrow-this" react>

Arrow functions don't have their own `this`; they use the `this` of the code around them. That's why they're perfect for callbacks inside methods.

<Playground file="arrow.js" expected={["3"]}>

```js
const timer = {
  seconds: 0,
  start() {
    [1, 2, 3].forEach(() => {
      this.seconds++;   // `this` is still timer
    });
    console.log(this.seconds);
  },
};

timer.start();
```

</Playground>
</Concept>

<Concept name="call() and apply()" id="call-apply">

`call` and `apply` run a function right now with the `this` you choose; `call` takes arguments one by one, `apply` takes an array.

<Playground file="call.js" expected={["Hi, Sara!", "Hello, Sara."]}>

```js
function greet(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}

const user = { name: "Sara" };
console.log(greet.call(user, "Hi", "!"));
console.log(greet.apply(user, ["Hello", "."]));
```

</Playground>
</Concept>

<Concept name="this in event handlers" id="this-events">

With `addEventListener` and a regular function, `this` is the element the listener is on; with an arrow function it isn't.

<Playground file="events.js" browserOnly expected={["~ After clicking the button:", "add-btn"]}>

```js
const button = document.querySelector("#add-btn");

button.addEventListener("click", function () {
  console.log(this.id);   // the button
});
```

</Playground>
</Concept>

<GoDeeper title="The four rules for this">

For a regular function, check these in order:

1. **`new Fn()`**: `this` is the brand-new object being created.
2. **`fn.call(obj)`, `fn.apply(obj)` or a `bind`-ed function**: `this` is `obj`.
3. **`obj.fn()`**: `this` is `obj` (whatever is left of the dot).
4. **Plain `fn()`**: `this` is `undefined` in strict mode (modules, classes) or the global object in old-style scripts.

Arrow functions skip all four and use the `this` of the surrounding code.

<Playground file="new.js" expected={["Tea"]}>

```js
function Item(name) {
  this.name = name;   // rule 1: `this` is the new object
}

const tea = new Item("Tea");
console.log(tea.name);
```

</Playground>

</GoDeeper>

<Exercise
  id="fix-lost-this"
  variant="fix"
  title="Fix the lost this"
  hints={[
    "`runTwice` calls `fn()` on its own, so `this` inside `increment` isn't `counter`.",
    "Pass a function that keeps `this`: `counter.increment.bind(counter)`, or `() => counter.increment()`.",
  ]}
>

`clickTwice()` should call `counter.increment` twice and return `2`, but it returns `NaN`. Fix `clickTwice` (leave `counter` and `runTwice` as they are).

```js starter
const counter = {
  count: 0,
  increment() {
    this.count++;
    return this.count;
  },
};

function runTwice(fn) {
  fn();
  return fn();
}

function clickTwice() {
  return runTwice(counter.increment);
}

console.log(clickTwice());
```

```js tests
test("returns 2", () => {
  counter.count = 0;
  expect(clickTwice()).toBe(2);
});

test("updates the counter itself", () => {
  counter.count = 0;
  clickTwice();
  expect(counter.count).toBe(2);
});
```

```js solution
const counter = {
  count: 0,
  increment() {
    this.count++;
    return this.count;
  },
};

function runTwice(fn) {
  fn();
  return fn();
}

function clickTwice() {
  return runTwice(counter.increment.bind(counter));
}

console.log(clickTwice());
```

</Exercise>
